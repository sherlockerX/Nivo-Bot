# Nicholasx本地测试修复

本页说明本地Android构建的兼容修复。不更改版本号，不提交或上传代码。

## 首次进入与聊天

欢迎页可选择“暂时跳过”，不配置供应商也能使用日记、资料库和设置。发送AI请求前仍需自行配置可用模型和密钥。跳过状态会保存，重启不再强制配置。

聊天标题和通知读取同一个真实任务时钟，不再以进入页面的时间作为任务起点。完成轮次保存开始、首输出、结束、状态和耗时；历史没有测量值时不估算。进程重新启动后，未完成记录标为中断，不宣称原请求仍在运行。可匹配的历史回答显示固定耗时。

思考与执行默认折叠，点击标题在底部面板里查看全部步骤，面板一次完全展开，返回一次即关闭，聊天里的回答位置不变；面板有自己的列表，执行中跟随最新一步，向上翻看后停止跟随，顶部两个按钮跳到第一步和最新一步。执行中标题同一行显示当前步骤，标题高度不变。此前已在聊天里展开的过程点击后收起。标题是固定高度的独立列表行，点击时在同一次测量中保留标题位置，不先跳转再逐帧修正。展开后的工具行按可见区域加载，长过程文本分片显示，不一次构建整段执行记录。对话锚点的索引同时包含展开后的过程行。界面保持长历史加载窗口，不一次渲染全部消息。

添加或编辑供应商时，“API Format”的 Chat Completions 和 Responses API 在任何屏幕宽度和字号下都一样大：同一排的选项高度一致，选中项不再显示占地方的对勾，只用底色区分。同样的处理用在图片生成、视频接口、定时任务的“发到哪里”和“重复”、思考强度和日志页的分段选项上。

## 教练页：成长训练

底部的「教练」页（原来的动态页）是能力训练场，旧信息流的逻辑已经去掉：没有帖子、点赞和“关于动态”卡，模型写的非训练内容一律丢弃，以前留在磁盘上的旧帖子不再显示。页面只放今天的训练卡，日期标题写成“今天 · 周日 · 2026年11月1日”，不分上午下午；往日的卡在训练日历里看。今天还没有卡时，页面上只有一张卡，写明每天几点自动写，并带“现在写一版”；没有在练的能力时改为提示先选一项能力。写卡失败会在这张卡上说明原因：没有模型、教练正在点评上一个回答、模型请求失败（附错误内容）或回复里没有训练卡。往日还有没答的卡时，日期下面有一行提示，点开日历定位到那天。

页首的卡片显示正在培养的能力、等级（入门、基础、熟练、精通、卓越）和升级进度，其余能力以小标签列出；点开是“能力与成长”面板，可以调整训练顺序、设为当前、暂停、添加自己的能力、设定练到哪一级换下一个（默认熟练），并查看成长记忆和我的原则。默认的六项能力依次是原则与判断、多视角分析、英语表达、表达力、领导力、习惯与执行力。六门预装课程都按建课框架做好了：每门 10 本书（核心 3、补充 5、对照 2，原则与判断以达利欧《原则》为主线），每本一张拆书卡，L1 到 L5 共 18 到 21 个单元；书单经过联网检索，版本信息对照了豆瓣、出版社或图书馆目录，凭记忆的要点在卡片里标了“未核实”。几门课之间有少量重复的书（如《思考，快与慢》《超预测》《关键对话》），课程里写明了各自讲的重点，学过的模型只复习。

教练页右上角左边是训练日历：按月显示，有卡的日子下面有一个点，点某一天就列出那天的卡、我的回答、分数和点评，没答的卡在日历里也能作答，删卡、讨论都和页面上一样；卡保留 90 天。右边是“训练设置”：每项能力由哪个技能训练（点开进入技能详情，可修改，另有“全部技能”入口）；出题用到的知识及其规模，包括 USER.md 和 GLOBAL.md 的字数、近 7 天拼图日记的条数和天数、近 7 天有几天每日记忆、进行中的目标、拼图日记里的习惯、成长档案的回答、回忆、原则和观察条数，以及挂载的文件夹（带“挂载文件夹”入口）；最后是引导语、每日生成开关和时间、现在写一版。挂载的文件夹会以沙盒路径写进生成提示，模型需要素材时可以读取里面的笔记，计入三次工具调用。

每天的定时生成先排课：正在培养的能力出一张理论卡和一张情景演练卡（升级挑战解锁后情景卡换成挑战卡；最近三天有三张没答时只出理论卡），最近 7 天没有待回报的现实行动时再布置一张现实行动卡；已经换走的能力中最久没练的一项出一张复习卡，等级越高复习间隔越长（2、3、7、14 天）。页面只出训练卡和周报，模型写的其他帖子（新闻、论文摘要等）一律丢弃，引导语只决定取材和侧重；想每天收到的资讯放进定时任务。写卡的例程提示词是“写今天的训练卡”，旧版本建的例程启动时自动换成这句，时间和开关保持不变；定时任务的输出约定（最终回复当通知、没内容回 NO_OUTPUT、超过 500 字只留 5 行）只注入用户自己的任务，不再注入教练和目标巡检，以前正是这段约定让模型不写卡。卡的编号不会重复使用：删掉的卡在成长记录里还有作答时，新卡跳过那个编号，不会继承旧卡的回答和分数；每天最多 12 张按现存的卡数算。

每项能力是一门课程，写在 `growth-*` 技能里：主线书目（原则与判断以达利欧《原则》为主线）、L1 到 L5 按顺序排好的单元、每个单元的理论要点、情景和现实行动、评分标准。卡片标明所属单元，生成提示里列出当前等级走过的单元和各类卡的得分，以及待回报的现实行动；一个单元的理论和一张情景或行动卡达到 3 分后进入下一个单元。技能首次启动时作为普通技能安装，可在技能页修改，生成时读取磁盘上的最新内容；没改过的预装技能在应用带来更高版本时自动更新，改过的保持原样。旧版预装的信息流引导语（`feed-preferences.md`）在内容未改动时换成教练用的引导语。生成的提示里还带着最近点评过的回答、等待点评的回答、成长记忆和原则库。

每张训练卡带一个问题和回答框，现实行动卡的回答是做完之后的报告。提交后，回答连同卡片内容立即作为一轮对话发到教练自己的隐藏会话里点评，卡片下显示 0 到 4 分和点评（情景卡附一个能照着做的应对方案，行动报告对照计划和结果给出下一次的调整），并可标记“太简单、合适、太难”，下一批卡片据此在本级内调整难度；正在写卡时等它结束，最长三分钟，没点评上的回答在下一次生成时补评，也可以点“重试”。

等级按掌握学习的做法由应用按固定规则移动：当前等级的情景和行动卡，最近 6 次点评平均不低于 3 分且分布在至少 4 天里，解锁一张升级挑战卡（比同级练习更难、综合本级内容）；挑战得 3 分及以上升一级，不到 3 分则保留最近 3 次练习，再练 3 次达标重新解锁。保持中的能力最近 3 次复习平均低于 1.5 分降一级；理论卡只点评和进入回忆，其他等级的卡片也不计入当前等级。正在培养的能力达到目标等级时，页首询问是否换到下一个，选“继续练这个”则到更高一级再问。页首同时显示今日已答几张、连续作答天数。

点评可以附一个值得记住的要点（问题和简短答案，比如改正后的英文表达、一条原则、某个视角的关键问题），进入“今日回忆”：像记忆卡一样先看问题、再显示答案，自评“忘了、模糊、记得”，间隔分别回到 1 天、约 1.3 倍、约 2.5 倍，最长 180 天，每天最多 5 条；忘过两次以上的要点会提示模型编进练习。每周日加一条周报：本周等级和得分的变化、难度反馈、一个反复出现的短板和下周重点。

每张卡底部的“讨论”新开一个对话，训练卡会带上能力、等级、单元、卡片内容、问题、我的回答和点评。

建课是一套固定的框架，写在预装技能 `growth-course-builder` 里，和用哪个模型无关：结构由框架定死，内容的好坏取决于模型的检索和拆书。“能力与成长”里每项能力都有“建课”，添加能力时可以“直接添加”（按通用方法训练）或“和 AI 建课”。建课会新开一个对话，第一条消息带上能力、想做到什么、课程文件夹、技能名和我的成长记录摘要；AI 照框架先问两三个问题，定目标和 5 到 8 个子能力，联网检索 15 到 25 本候选，按覆盖、经典程度、证据、适配和重复度选出 10 本（核心 3、补充 5、对照 2），书单发给我确认后逐本拆书，再跨书合成 L1 到 L5 的单元，最后按清单自检。拆书优先用我挂载进沙箱的电子书或笔记，其次是目录、试读、作者的演讲文章和可靠书评；每条要点标来源，凭记忆的标“未核实”，不下载盗版、不大段引用。文件夹里已经有课程时就是重建，我的框架和调整记录保留。

一门课是技能文件夹 `/var/minis/skills/<技能名>/`：`SKILL.md`（目标、框架、书单、分级单元、打分）、`books/B01-…md` 到 `B10`（拆书卡：主旨、4 到 7 个可迁移模型及其失效条件、做法、常见误读、来源）、`FRAMEWORK.md`（我的框架）、`ADJUSTMENTS.md`（课程调整记录）。每天出卡时，正在培养的能力的拆书卡（最多约 12000 字）、我的框架和最近 12 条调整一起写进生成提示，理论卡讲拆书卡里的模型并注明出处。教练在一个单元完成时和每周日用 `nanomuse-framework` 块重写我的框架（每个子能力一节：学到的模型、我的案例、我现在的原则或做法），应用写进 `FRAMEWORK.md`；现实反馈说明课程要改时（重复、补课、跳过、换书、调顺序），用 `nanomuse-course` 块写一行，应用追加进 `ADJUSTMENTS.md`，之后每天提示里都带着。“能力与成长”里能展开当前能力的“我的框架”，每项能力下显示拆书卡张数；“训练设置”里显示拆书卡张数和框架字数。预装课程的拆书卡随技能一起安装，没改过的随应用升级更新，改过的保持原样。

记录在 `minis-global/nanomuse/growth/`：`state.json`（能力、顺序、等级、近期得分、挑战状态）、`responses.jsonl`（每次回答、点评和难度反馈，保留最近 500 条）、`recall.json`（回忆要点和下次时间）、`MEMORY.md`（学习特点的摘要，每周日或观察积累到 20 条时由模型重写）、`observations.md`（点评时逐条记下的观察，重写摘要后清空）、`PRINCIPLES.md`（我在回答中采纳或改写的原则）。训练卡本身在 `minis-global/nanomuse/feed/<日期>/NN.md`，保留 90 天。写卡时最多调用三次工具，习惯训练会用 `minis-jigsaw-cli` 读打卡。

## 沙盒与工具

- `/var/minis/home`跨会话持久共享：稳定脚本放在`bin`，状态放在`state`，日志放在`logs`。账户切换时随账户隔离。
- `/var/minis/workspace`、`attachments`、`offloads`、`browser`仍属于当前会话。旧路径和文件不迁移、不删除；归档不意味着删除目录。旧`shared`继续有效。
- 正常空目录的`ls`仍成功退出0。合法空查询保留退出码0，通过`status=empty`表达；权限、读取、依赖和解析故障不以空列表掩盖。未采用退出码10，避免旧工具把合法空当作执行失败。
- `minis-jigsaw-cli list --days 2 --until 2026-10-27`包含10月26日和27日。`queried`回显实际分页窗口，时区仍为`Asia/Shanghai`。记录级和日级新增`energy`，越大越好；旧`mood`仍是1最好、5最差，不反转历史数据。不读取图片。
- 日历终点未知时返回`end=null`、`duration_unknown=true`，有合法`DURATION`则计算终点。空闲查询使用系统事件实例，覆盖重复和时长事件。[Android实例接口](https://developer.android.com/reference/android/provider/CalendarContract.Instances)

## 分组与定时任务

```sh
minis-sessions-cli groups list
minis-sessions-cli groups create --name 工作
minis-sessions-cli groups rename --id GROUP --name 学习
minis-sessions-cli move --id SESSION --group GROUP
minis-sessions-cli move --id SESSION --group none
minis-sessions-cli pin --id SESSION
minis-sessions-cli pin --id SESSION --unpin
minis-sessions-cli groups delete --id GROUP
minis-scheduled probe --id TASK
minis-scheduled create --label 日常检查 --time 09:00 --repeat daily --script daily.sh
```

新建的对话一律在“未分组”，包括从回答处分支出来的对话（不再跟随原对话的分组）。“自动归类”默认关闭：以前它在第一轮回答后让标题模型从已有分组里挑一个，“日常”这类宽泛的分组几乎每次都被挑中；需要时可在 设置 → 外观 → 自动归类 打开，打开后也不会把对话放进“定时任务”组。已经被归进去的对话不自动搬回，可以手动移出。

解散分组只清除归属，不删除聊天。仅能关联到实际保存的用户任务的新运行进入“定时任务”组，内置Feed、目标活动及来源不明的历史会话不自动搬入。追加或重跑目标保持原归属，用户手动分组优先。系统组默认收起，普通移动与AI建议均不把它作为目标。CLI保留旧日期字符串，新增毫秒字段及分组、置顶和轮次计时信息。

显式脚本任务只接受`home/bin`下的安全文件名，支持`.sh`和`.py`。预检检查文件、解释器、参数和设备时区数据，不执行业务脚本，也不保证网络服务可用；执行仍走风险闸门，使用审批时的脚本快照。重复的`--script-arg`形成独立argv，最多16项、每项最多256字节，空格及Shell符号按字面传递，不拼接Shell命令。进程不等待用户输入，stdout与stderr并行排空，取消会终止执行。

任务结果分为success、failure和unknown。脚本退出码为准；模型任务遇到传输失败、取消或明确失败上报才记失败，没有可验证结果为unknown，不把回答文本当作执行证明。unknown不清零失败计数，CLI运行返回码为3。模型的结果上报同时校验运行身份、短期令牌和真实子进程来源，不能通过普通对话伪造。任务取消与重跑使用同一稳定父Job覆盖准备和执行。

同一自动触发时间槽只结算一次，已派发但中断的业务不自动重放。主结算失败保留收据，只恢复写入结果。默认连续失败两次更新同一条通知，后续失败不堆叠；明确成功后移除旧告警，unknown保留。显式开启`--auto-disable-on-failure`才采用停用策略，停用时再次提醒。旧计数不回推不存在的历史证据。

本地运行日志位于`home/logs/scheduled/<task>/<上海日期>.jsonl`，每个任务保留30天且总量不超过5MiB，目录0700、文件0600，不跟随最终文件符号链接。默认仅记录输出字节数、哈希、stderr尾部和落库计量，只有`--log-stdout`明确开启才保存stdout正文。`minis-scheduled logs --id TASK --last 20`查询，空结果包含查询窗口。任务删除保留日志，在后续启动和心跳中继续轮转，不需要再次运行已删除任务，也不删除会话；日志失败不改变业务结果，标记log_write_error并在后续写入补记。兼容任务存储仍是本地SharedPreferences，`home/state/scheduled/<task>.json`是原子导出镜像；IO失败时不能声称镜像已同步。

stdout为空且正常退出时记录CompletedEmpty，并显示系统说明，不伪造assistant回答。`--require-output`开启后空输出算失败。消息保存采用固定运行消息ID，初次失败后依次等待200ms、1s、3s重试，耗尽后显示MESSAGE_WRITE_FAILED。读取接口始终包含text和布尔truncated字段。间歇性空正文的根因尚未被真实场景复现，本轮建立计量和防御，不宣称已根治。

一次运行最多一条结果通知，同一任务在通知栏只保留一条（tag为`sched:<task>`，新的替换旧的），成功的结果点击打开这个任务的专属对话，失败通知打开运行记录。定时运行不再额外弹出“点击打开聊天查看回复”。通知正文只来自结果：脚本取去掉首尾空行的stdout，全空白不通知；提示词任务优先取`minis-scheduled report --result TEXT`，其次是最后一次工具调用之后的回答，模型回复`NO_OUTPUT`或剥离过程说明后为空时不通知。每次提示词运行都注入输出约定，旧任务同样生效，任务里保存的提示词不变。

```sh
minis-scheduled create ... --notify always|on_change|on_failure|never --notify-title 今日简报 --silent
minis-scheduled create ... --debug
minis-scheduled update --id TASK --notify always
minis-scheduled run --id TASK --dry-notify
minis-scheduled settings --quiet-hours 01:00-08:00
```

`--notify`默认`on_change`：6小时内结果相同不再推送。首次失败推一条“任务名 失败”，正文是错误输出的最后一行；之后的连续失败由失败提醒负责，提醒取代该任务的结果通知，不再推第二条。同一任务60秒内再次推送不响铃，全局一小时超过10条后合并为一条“N 个定时任务有更新”，静音时段（默认01:00-08:00）静默入栏。每个任务固定一个专属对话：第一次运行时在“定时任务”组里建，标题是任务名，之后每次运行都写进去（取这个任务建过的对话里最近活动的那个；删掉它，下次运行再建一个）。脚本任务每次先写一行“例程 · 任务名 · 时间”，再写结果（有`report --result`时写它，否则写stdout），每次的结果各成一条；`--session-output`仍可接受，不再改变行为。记录来源之前建的任务（legacy）只要不隐藏、不属于目标，同样归入“定时任务”组。对话越写越长，定时运行不再停在“是否压缩”的询问上，交给第一轮之前的上下文检查直接压缩。`--debug`不推通知、脚本运行不建对话、不计失败；`run --dry-notify`照常执行并记录，只是不推送。日志和运行记录新增result、result_source、result_hash、notified、notify_suppressed_reason等字段，运行记录页显示结果全文、退出码、错误输出最后一行和未通知的原因。删除任务时撤回它的结果通知。`android-notification cancel --id`接受负数，并按`list`给出的id和tag取消本应用的通知。

通知栏里有两条以上定时任务结果时才成组并出现分组摘要，标题是“N 个定时任务有更新”，正文是最近一条的任务名；只剩一条或没有时摘要撤掉，不再留一行空白的“定时任务”。系统撤摘要会连同组内通知一起撤，所以剩下的那条先原地移出分组（不再响铃），再撤摘要。

脚本的stderr与proot共用一根管道，proot退出时会打印几KB的talloc内存报告。捕获在这份报告固定的首行处截断，`stderr_tail`只含脚本自己的错误输出（最后2048字节，从行首开始），`stderr_bytes_total`是脚本写入的总字节数，`stderr_truncated_from_head`表示开头被截掉。失败通知的正文依次取明确上报的失败原因、错误输出的最后一行、“退出码 N，没有错误输出”。脚本运行里`minis-scheduled report`不打印回执（退出码0即已接受），`--result`优先于stdout成为结果；脚本退出码0但上报`--status failure`时记失败。

“定时任务”分组就是归档：侧栏默认收起，`minis-sessions-cli list`默认不列，消息保持不变。

```sh
minis-sessions-cli list --include-archived
minis-sessions-cli archive --id SESSION,SESSION     # 只收定时任务建的会话
minis-sessions-cli unarchive --id SESSION
minis-sessions-cli delete --id SESSION              # 只报会删掉的会话数和消息数
minis-sessions-cli delete --id SESSION --force
```

点名`--ids`时照常列出归档会话，`search`和`messages`仍能读到它们。删除经过风险闸门，跳过主聊天、执行中、任务追加目标和隐藏的会话，在`protected`里列出。任务新建的会话一开始就在归档里，因此不另设保留条数，也不自动删除旧会话。

分组名经过trim、NFKC及完整Unicode大小写折叠，数据库唯一索引兜底并发冲突，错误保留稳定代码及既有分组ID。升级前备份元数据，旧重名组只稳定编号，不合并、不搬动成员。侧栏提供明确多选入口、数量、当前搜索范围和分组全选、删除确认。主聊天、执行或排队中的会话及任务绑定目标受保护，确认时重新校验；可删除项通过数据库事务处理，失败不会提前清空选择。

## 语音

设置 → 模型 里有“语音转文字”和“文字转语音”两行，打开的是应用原有的语音模型选择器，选中的模型用于语音输入、朗读和快速测试。手动添加的语音模型按名字识别：qwen3-asr-flash、fun-asr-realtime、paraformer 系列算语音转文字，cosyvoice、sambert、qwen3-tts-flash 等算文字转语音；这些模型不再出现在对话模型的列表里。

阿里云百炼的 OpenAI 兼容模式没有 `/audio/transcriptions` 和 `/audio/speech`，所以百炼的语音按模型分开走：fun-asr-realtime、paraformer-realtime 和 CosyVoice 走语音通话用的同一个 WebSocket；qwen3-asr-flash 和 omni 模型走对话接口，录音以 `data:audio/wav;base64,…` 发送；Qwen-TTS 走百炼原生的多模态生成接口，下载返回的 WAV。CosyVoice 没指定音色时，v3 用 longanyang，v2 用 longxiaochun_v2。其他百炼模型直接提示该换哪几个模型。业务空间地址（`<id>.cn-beijing.maas.aliyuncs.com`）同样按百炼处理。

语音通话可以打断：识别在模型思考和说话时也开着，开口说两个字以上、且不像是它自己的声音（和正在说的内容重合不到一半）时，回答立即停止，说的话成为下一轮；也可以点“打断”。识别在回答期间也计费。通话用的模型仍在通话页右上角的设置里单独选，因为通话只能用百炼的实时模型。

## MCP、通知和记忆

MCP复用现有headers、环境变量和OAuth配置。401/403明确返回需要授权，不回显服务器原始错误正文。已确认不可用的服务器暂不进入模型推荐清单，配置页仍可重新检测；配置修改或短期状态过期后可重试。环境变量更改后的旧daemon环境需要重建进程，不能把“已保存凭据”当作连接已检测成功。

旧Alpine镜像按需通过`apk`补Python和httpx，补装后再次验证import；失败明确退出，不继续假装运行。依赖安装和daemon日志限制大小。定时任务上下文使用设备IANA时区，旧镜像缺少数据时从Android公共时区库提取当前TZif并只读绑定。设备时区改变时补齐当前区域，必要时重建Shell挂载；无法提供实际数据则预检失败，不静默退回UTC。

通知发送支持`--tag`，同tag更新、不同tag互不覆盖，延迟发送和取消沿用相同身份。`cancel --tag TAG`仅取消本应用对应通知；默认清理只作用于本应用。跨应用取消必须显式指定`--package`，且监听已授权并连接，系统可能保留受保护通知。

新持久化且开启记忆的对话产生确定性事件摘要，保存于`memory/events`，`memory/EVENTS.md`列出最近七天事件与每日日志情况。不读取图片，不把assistant文字当作工具成功证明，不伪造缺失日期的日记。人工记忆保持原格式；历史消息完整重放不属于当前事件投影。

## 验证边界

模拟器使用独立`.uitest`应用，不清除原应用数据，不填写真实密钥。调试包的`debug.scheduled.exec`和`debug.notification.exec`可直接调用`minis-scheduled`与`android-notification`，正式包不包含。x86_64模拟器包不带aarch64沙盒镜像，脚本任务只能验证预检失败路径，实际执行（包括stderr截断和脚本内的`report --result`）需在arm64设备上验证。云端模型、MCP实网授权、手机省电策略和arm64沙盒执行仍需设备验证。有限测试不能保证所有场景绝不卡顿，以测试记录中的覆盖项为准。
