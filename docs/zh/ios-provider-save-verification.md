# iOS供应商保存修复验证

本次修复基于2.0.6维护分支。用户报告新增自定义供应商出现“无法保存，未能打开该文件，因为它的格式不正确”。
当前测试已复现相同的Cocoa259错误出现在旧SQLite快照的重复校验和恢复路径；
首次新增的独立文件事务测试通过，因此尚不能将恢复缺陷认定为手机上最初失败的唯一原因。

## 已确定的问题与修复 {#confirmed-defects-and-repairs}

- 只读校验WAL快照会生成额外辅助文件，旧恢复清单拒绝这些文件。新快照封存为单文件，
  旧快照仅接受已登记SQLite载荷的精确WAL/SHM配对，恢复保留WAL中已提交的记录。
- 自定义模型改ID原来按新ID寻找原记录。现在按UUID定位，拒绝同供应商内的ID冲突，
  并更新组成员、会话与智能体引用。
- 模型表单和新建分组原来在持久化完成前返回成功。现在等待数据库与JSON写入，失败保留输入。
  补偿以提交候选为基线，避免并发保存失败时留下本次未成功提交的模型。
- 详情页刷新模型在发布前核对来源实例和恢复代次。
- 旧模型补全能力时保留原UUID与人工编辑时间；删除分组同时清理对应语音选择。
- 重置未知上下文长度会清空旧输入；修改名称和ID保留未编辑的推理档位、思考上限，以及专用语音和视频模型的输入、输出方向。
- 供应商保存错误增加无敏感信息的阶段代码，首次失败和回滚失败分别记录。

## 验证范围 {#verification-scope}

便携测试使用真实临时文件和SQLite，覆盖快照校验、提交与回滚边界、旧WAL恢复、身份冲突及引用重映射。
Apple宿主集成测试额外覆盖真实ProviderConfigStore和ProviderConfigDB，包括数据库已写入而JSON镜像失败后的补偿与重试。

Windows不能运行Apple宿主测试；GitHub的设备构建和测试目标编译也不代表这些宿主测试已经执行。
这些检查不会连接实际模型供应商或读取用户密钥。

## iPhone复测 {#iphone-acceptance-steps}

1. 用相同签名身份覆盖安装修复IPA，保留应用数据。
2. 打开模型设置，添加自定义供应商，填写名称、自己的地址与密钥。保存后确认列表中出现一次，
   退出应用再打开，检查地址与模型配置仍在。
3. 为该供应商新增一个自定义模型，保存后重开编辑页。把模型ID改为另一个未使用ID，确认分组仍引用它。
4. 同一供应商添加第二个模型，尝试把第一个模型的ID改成第二个的ID。应显示冲突，两个原模型都保持原样。
5. 创建模型分组并选为语音输入或输出分组，再删除该分组。语音选择应回到未选择。
6. 刷新模型列表，确认有加载反馈；网络失败时应显示错误并保留现有配置。
7. 用自己已配置的模型发送一条消息，验证实际API连接。
8. 给语音或视频模型改名，检查能力不变。对基础上下文长度未知的模型执行重置并再次保存，确认旧覆盖值没有回来。
9. 如果仍有保存错误，记录完整`PV-`诊断代码及发生在新增供应商、编辑密钥、导入JSON还是编辑模型。
   不需要提供API密钥。

## 诊断代码 {#diagnostic-codes}

`PV-阶段-错误码`只描述失败位置。`01`为读取保存基线，`02`为候选校验，`03`为回滚快照，
`04`为恢复日志准备，`05`为凭证，`06`为配置写入，`07`为提交清理，`08`为失败回滚。
末尾数字是NSError桥接码；对于Swift错误，它不一定等于SQLite或Keychain的底层状态码。
恢复失败时保留恢复材料；不要通过卸载应用或删除数据库尝试绕过。
