# Android App

## 本地模式 {#local-mode}

这个Android构建无需nanoMuse账号。内置登录与账号验证、nanoMuse Cloud模型中继、远程设备hub、对话与资料同步均已停用。请在「设置→模型」中添加自己的API端点或受支持的服务商OAuth账号。自有MCP服务器、连接器、网络代理及其他第三方服务继续连接各自配置的服务。

Debug与Release均可跳过首次引导，重启后继续保留该选择。应用移除固定项目官网、GitHub、Star、问题反馈和GitHub技能目录入口，保留从用户指定文件或URL导入技能。「关于」继续显示GPL许可信息。

内置服务商列表过滤目录中标记为`is_relay`的条目，包括OpenRouter、SiliconFlow、OpenCode、Standard Compute和CheaperInference。已有配置与OAuth凭据继续可用，也可自行填写兼容端点。旧额度消息只引导打开服务商设置，不再显示邀请、项目链接或中转站推荐。

在已有应用数据容器内，本地模式保留当前数据归属、聊天、任务、文件和服务商配置。原内置Cloud服务商会被禁用，并从服务商设置中隐藏；它的ID、密钥、模型和分组绑定仍保留，旧记录不会因此被删除或重新分配。旧聊天仍指向Cloud模型时，需要先选择自己的服务商再发送。已有账号归档继续保存在原处，不会自动合并到当前工作区。全新安装使用本地归属。

Nivo的Android2.0.10使用`io.github.nivo`。已发布的Android`2.0.9(60)`使用`io.github.sherlockerx.nelan`，更早的版本使用`io.github.nanomuse.app`。每个包名的私有存储、凭据与系统授权彼此独立。请保留旧安装，按[迁移说明](../releases/v2.0.9.md#moving-from-the-old-android-package)导出与导入已支持的内容。通用备份不迁移心得及照片、教练进度、专注历史或自定义宠物。

聊天等待回复时会显示三颗交替闪动的星星，推理进行中也会出现在步骤标题旁。工具运行时显示工具自己的状态；正文开始后星星消失。关闭系统动画时，三颗星保持静止。

过程摘要放在回答上方，与回答同一左边线，宽度随文字：一张细描边小卡片，依次是图标、标题（只有思考时写「正在思考」或「思考过程」，用过工具时写「思考与执行中」或「思考与执行过程」）、工具数和箭头；执行中第二行写出当前步骤。点按后以时间线查看全部步骤：每一步左侧一个节点（思考是灯泡，说明是圆点，工具按进行中、完成、失败、取消分别显示转圈、对勾、叉号和短横），节点之间用细线相连，工具详情、停止和跳至首个或最新步骤的入口继续可用。时间线里较长的思考默认只显示前三行，点「展开全部」查看；正在输出的那段保持展开，结束后自动收起，展开后可点「收起」（iPhone上点标题的箭头）。展开的思考内容标题左对齐，正文左侧一条细线；等待回复提示只显示星形和文字。文字使用主题的次要文字色，只有进行中的图标使用强调色，深浅模式一致。

应用通过`allowBackup="false"`关闭Android系统自动云备份，保留用户主动导出、导入和自行配置的备份目的地。重装后不会从原账号服务取回聊天，卸载前请保存手动备份。

## 个人待办 {#personal-tasks}

从聊天侧栏“点子”下方打开**待办**。右上角模块菜单提供日历、四象限、分组、状态和完成统计。新建只需填写标题，按需补充备注、计划日期、截止日期、一个分组和多个标签。重要与紧急由你明确选择；截止日期不会自动建立提醒或定时AI任务。

待办界面采用统一浅深色卡片、状态概览和紧凑搜索。列表底部沿用点子页的画布与渐变过渡，使用悬浮胶囊快速添加；列表按输入栏实际高度预留空间，适配多行输入与键盘。胶囊内的选项图标打开详细新建，任务左侧状态按钮可直接完成或重开；未完成任务优先显示。子视图保留轻量新增入口，右上菜单标明当前模块。编辑与详情使用可滚动的底部面板，日期可通过日历选择或清除；大字号日历显示可滚动日期条，四象限先选摘要再查看任务。统计环形图中心显示真实完成数量，图例可下钻。

分组与标签现在有独立保存的目录。编辑任务时点击分组进行单选、点击标签进行多选，可以搜索已有名称或明确创建新名称；取消任务编辑或删除任务后，已创建分类仍可复用。右上“分组与标签”模块支持先创建分类，空分组也会显示在分组视图。升级时自动收集已有任务的分类，AI创建任务也复用同一目录。

本地待办备份升级为版本2，包含尚未使用的分组和标签；仍可读取版本1，并从导入任务补全目录。目录按当前账号隔离，丢弃该账号本地数据时一起清理。完成时的标签快照保持原样。聊天工具可通过`kind: "categories"`配合搜索和分页查询后再选用名称。

主要聊天可以通过原生工具查询、创建和更新同一份待办。完成操作需要当前用户回合的明确完成报告；工具持久化成功后才返回成功，普通生成文字不会创建任务。也可直接在页面管理任务，无需使用模型。

修改会在工具入口与数据库事务内核对`expectedRevision`。版本不符时返回`code: "stale_revision"`、任务ID及期望/实际版本，不改任务或历史；调用方需重新查询后再提交。对已成功的`operationId`进行完全相同的重试，会返回首次结果，不再次写入，也不覆盖之后的修改；同ID换内容会被拒绝。搜索匹配当前内容和任务ID，也可用`dateField: "created"`按设备本地创建日期查询；旧标题不保留检索索引。

点子、个人资料及设备入口发起外部请求时，如果聊天里已有草稿、编辑目标、附件或粘贴内容，会保留当前输入并提示先处理。聊天内部点击点子仍可明确追加文字，由你确认发送。隐藏聊天暂停流式展示计算，返回时读取最新状态；模型请求与保存继续执行。

在每日碎片里选择关联待办，再选择“仅关联”“进行中”或“已完成”。完成日期单独显示，补录以前的活动时可以选择过去日期。任务选择随草稿保存，正式保存碎片与更新任务在同一事务完成；发生冲突时保留草稿供重新确认。重新打开碎片不会重放旧状态；删除碎片保留任务，删除任务保留既有碎片中的历史快照。

完成统计提供日、周、月、年视图，依据完成日期及完成时标签快照计算。每项任务权重为1，多标签均分，未标记单列。图表同时显示占比和涉及任务数，反映已完成事项分布，不代表耗时或精力。重开或删除任务会移除其贡献，过去周期的统计也会相应变化。点击扇区或图例可以回看任务与关联碎片。

待办及关联属于当前本地账号，既有每日碎片沿用设备级存储方式。右上菜单提供版本化JSON本地导出和导入，包含任务、状态历史及重复操作记录；同ID保留本地编辑，结果提示缺失的碎片关联。备份不含照片，与通用应用备份分开，不启用云端任务同步。


## 教练探索 {#coach-exploration}

教练页沿用聊天画布和紧凑的右上入口，课程页与练习页显示主题矢量场景：原则与判断对应竹海，多视角对应圆桌辩论，英语对应交流窗口，表达对应发言舞台，领导力对应协作工作台，执行力对应行动步道；自定义课程使用罗盘。插画在本地绘制，不持续播放动画。

教练页先列出你的全部技能。有没练完的课节时，最上方有一张卡可以接着练。每张技能卡显示当前单元、已达成的单元数和今天的状态（进行中、今天已练、有未完成的课节、已暂停、标准待审阅）；「添加技能」进入课程库，可以和AI一起设计新技能，查看草案和来源。点一项技能进入它的档案：进度和暂停、审阅标准等操作，今日训练，按单元列出的学习内容（达成的单元打勾，当前单元有标记；点开单元看它的目标、练法和达成标准，当前单元里还有下次安排的依据和本次教案用到的概念与材料），当前表现，以及按日期排列的历次训练。列表页的标题栏只有训练日历和教练设置两个入口，其他页面都有返回箭头。只有点训练按钮才会进入对话。进度来自保存的证据，浏览页面不会标记掌握。

「教练设置」写明备课智能体做什么、不能做什么，可以开关它（关闭后开课直接使用课程里的基础练习，不调用模型），选择它用的模型（默认跟随聊天，也可以另选一个文字模型），设置默认训练时长。这一页还列出每门课程读取的skill及版本、最近五次备课的模型、调用次数和用时（或改用基础练习的原因），并提供课程库、训练日历和旧版训练设置的入口。

`android/` 是手机上的 nanoMuse：[OpenMinis](https://github.com/OpenMinis/OpenMinis)
1.13（GPL-3.0）：一个原生 App，智能体**在手机上**运行，Linux shell、浏览器、MCP 服务器、
技能和定时任务都装在 APK 里，再加上 nanoMuse 自己的身份、设计和功能。属于 nanoMuse 的一切
都在 `io.github.nanomuse.*` 下；OpenMinis 文件里的改动用 `// nanoMuse:` 标出。应用ID为
`io.github.nivo`，系统URL scheme保留`nanomuse://`，与OpenMinis区分。
旧安装也可响应这个外部scheme；并装时系统可能询问用哪个应用打开链接。
App内部的链接仍是`minis://…`（上游的词汇，沙箱、
系统提示词和模型都用它），从系统进来的 `nanomuse://` 链接按它的 `minis://` 形式读，App 自己打开
自己的链接时一律按名字指向 `MainActivity`，不交给系统去解析
（`io.github.nanomuse.deeplink.OwnScheme`）。沙箱的 offload 套接字（proot 和 App 之间通信的
抽象套接字）也是App自己的：叫`io.github.nivo.native-offload`，不用上游的
`native-offload`，因为抽象套接字在整台设备上只有一个命名空间，两个 App 用同一个名字，后启动的那个
会在启动时直接死掉；如果连这个名字都还被我们自己上一个进程占着，服务端就改绑一个带进程号的名字，
并把它告诉 proot（`io.github.nanomuse.sandbox.OffloadSocketName`）。这个选择的来龙去脉
在 [roadmap.md](roadmap.md)；它之前的方案（包着一个 Python 服务器的 WebView，两个 APK 变体）
作为设计记录保留在 [archive/android-python-line.md](../archive/android-python-line.md)，不是你今天
下载到的东西。

正式包面向arm64-v8a、Android8.0／API26及以上，`targetSdk`为35。
Android`2.0.10(61)`的文件与安装要求见[发行说明](../releases/v2.0.10.md)。新版与旧包名的应用并存。

## 安装 {#install}

1. 从本分支[发行页面](https://github.com/sherlockerX/Nivo-Bot/releases)选择APK，并使用同版校验文件核对。
   请先查看[跨包迁移指南](https://nivo.8666886.xyz/install.html#android-migration)，保留未能转移的旧数据。
2. 打开它。Android 会问一次，是否允许从你的浏览器或文件管理器安装。
3. **添加自己的模型。** 打开「设置→模型」，添加API key、兼容端点或受支持的服务商OAuth账号。按服务商能力设置「对话」「操作屏幕」「生成图片」「生成视频」。每组默认显示8个模型，点「还有N个」可展开，较长列表可按模型ID或名称搜索。对话模型选择用于主要聊天和新对话，已打开的旁聊保留原选择；其余三项支持「自动」。尚未配置可用服务商时，发送前会提示选择模型。

4. 可选：让智能体能使用你手机上其他 App 的那两个权限（可跳过、可撤销）。「设置 → Hands」
   仍保留屏幕模型那一行，点开是同一个选择页；「模型」页底部的「更多图片和视频选项」就是原来的
   「图像与视频模型」页（手动输入模型名、缺了哪个模型会停下什么、重新检查一把 key 能用哪些
   视频模型），也在 `minis://settings/media`。

**用它来做什么。** 保存一个你自己的服务商之后（新建的，或给原本没有 key 的补上 key），会有一张
卡片问这把 key 负责哪些事：目录里该厂商每有一项能力就有一个开关（对话、操作屏幕、生成图片、
生成视频），默认全开。「就这样」把勾选的几行切到这个服务商，模型用目录里该项的默认
（`providers.json` 的 `defaults.chat` 等），默认不在它的列表里时用列表里第一个能做这件事的；
「暂不」什么都不改，没勾的开关也一样，其他模型选择保持原样。以后在「模型」页改。

**你没选的时候。** 对话使用第一个可用的自有服务商；屏幕、图片和视频优先使用对话服务商具备的相应能力，否则选择其他符合条件的自有服务商。明确选择的模型优先。内置Cloud不参与选择或错误重试；本地模型服务器和第三方网关仍可作为自己的服务商添加。

## 手机能做什么 {#what-the-phone-does}

Shell 的进度更新会保留较短覆盖后未被改写的文字。终端的颜色和标题控制码会先移除，避免覆盖后在输出中留下转义序列的残片。

| | |
| --- | --- |
| **智能体，在手机上** | 一个沙箱里的 Alpine Linux、一个真正的 shell、文件、浏览器、MCP 服务器、Agent Skills 格式的技能、记忆、定时任务；删除、发送、付款之前先审批。模型来自自行配置的服务商，项目内置中继已经停用。 |
| **手（Hands）**（`hands/`） | 打开「Hands」并启用无障碍服务之后，智能体会看手机的屏幕，在各个 App 里点、输入、滑动：这是 API、抓取和浏览器之后的最后一级。盖在 App 上的舞台显示它即将点哪里，一个胶囊显示当前步骤和**停止**；屏幕边缘有一圈呼吸的光（干活时蓝色，等你时琥珀色；亮 2.4 s、暗 2.4 s，第 9 轮起每个客户端上每一处「在干活」的灯都是这个节奏：没有东西绕着边缘跑，也没有东西从屏幕上扫下来，胶囊的环和竖条按同样的节奏呼吸；系统设了「减弱动态效果」时全部静止）；当一次点击会发送、发布或删除时，胶囊自己就会问（**允许** / **拒绝**，和聊天卡片、通知显示的是同一个请求），所以你不用被拉回 nanoMuse（付款在聊天卡片里用锁屏确认；对这一种，胶囊提供「打开」）；胶囊只回答它自己的请求，不会替另一段对话的命令行或浏览器卡片作答，卡片等待期间按**停止**会直接拒绝它并立刻结束这次运行。密码和验证码永远由你自己输。屏幕没有变化而同一个动作做到第三次，历史里会记一笔，好让模型换个法子；做到第六次，这一轮就以「做不到」结束并写明是哪个动作（`HandsLoopWatch`，运行时也有同样的底线），而不是每一步都调用一次模型，直到三十分钟上限。每一步的截图写在会话的 `attachments/hands/<run>/` 下、与这次运行的轨迹放在一起；最新的十次运行保留全部截图，更早的运行只保留轨迹和最后一张屏幕（聊天里显示的那张），超过 200 次之后最早的一次整个删除（`HandsTraces`）。[gui.md](gui.md) 是设计记录；App 自己的手在 `io.github.nanomuse.hands`。 |
| **交到你手里的浏览器**（`browser/`） | 需要你亲自处理的页面（登录、验证码、付款、人机验证）会直接交到你手里，而不是用文字描述：`browser_use` 的 `hand_over` 动作把智能体自己的标签页（同一个 WebView、同一个会话）在浏览器面板里打开，智能体松手；输入框上方的**轮到你了**卡片说明页面要你做什么，带「打开页面」和「完成，继续」，面板上是同一句话和同一个按钮，工具调用会等到「完成」（最多十五分钟），然后智能体从页面当前的样子接着往下做。`io.github.nanomuse.browser.BrowserHandOver`。 |
| **连接器**（`connectors/`、`ui/connectors/`） | 智能体可以被放进去的那些服务：桌面版那份 75 个远程 MCP 服务器的目录（Notion、Linear、GitHub、GitLab、Slack、Stripe、Miro……），以 `assets/nanomuse/connectors.json` 随 App 发布。设置里管这一切的只有一行：「连接器」；上游的 MCP 编辑器（按地址、按命令、导入 JSON）是页面末尾的「你自己的服务器」。开放的服务点一下就加上；要 key 的服务填 key；OAuth 服务走 MCP 授权流程（发现、动态客户端注册、在 Custom Tab 里做 PKCE），令牌进入该条目的 `Authorization` 头，供沙箱内的 MCP 客户端使用，App 启动时刷新；授权服务器不接受注册客户端的服务（`clientIdRequired`：GitHub、Slack、Discord、HubSpot、Render、Bitrise、PagerDuty、Box）会要你在厂商的开发者页面用 App 的回调地址创建一对 OAuth client id 和 secret，面板会显示并复制这个回调地址。连接好的服务就是同一个 id 下的一个 MCP 服务器条目；「你自己的服务器」也能管它。连接只在本机管理，内置资料分享和其他设备连接列表已经停用。 |
| **聊天，不花哨** | 智能体工作时，形象下面那一行写的是正在进行的步骤（「nanoMuse 正在用 Shell」「正在写回复」「在做了：订餐桌」），从不写心情。工具小标签、「电脑」面板和浮动的步骤条从 0.1.37 起**默认打开**；「设置 → 外观 → 显示智能体的步骤」可以关掉它们。打开时，完成的步骤显示为「nanoMuse 用过 Shell · 完成」，它的面板点 ×、滑动或返回键都能关。 |

聊天和胶囊栏、菜单、抽屉在同一块底色上：深色主题是纯黑，浅色主题是纯白。你的消息是白色胶囊、黑色文字（浅色主题下反过来，黑色胶囊、白色文字），

最新消息和工具小标签都可以完整滚动到它们上方。对话仍会滚过导航胶囊背后，
保留磨砂模糊效果。输入框展开、工具预览或审批卡片出现时，间距跟着底部区域的实际高度调整。
审批卡片本身最多占屏幕的三分之二：超过六行的命令折叠在「全部显示」后面，说明和预览在中间滚动，「允许」和「拒绝」始终留在底部可见。

只有当前浏览器操作的步骤条、浏览器面板或「轮到你了」操作卡片显示时，这层渐隐才会隐藏；历史工具小标签和其他工具不会关闭它。

## 自己的 key {#your-own-key}

App 认识的厂商在一个文件里，`assets/nanomuse/providers.json`，运行时的
`nanomuse/llm/providers.json` 的一份拷贝，由 `node scripts/providers-json.mjs` 写出，每个客户端读的
都是这同一份目录（[own-key.md](own-key.md)）。每个条目写明端点在哪、在哪里创建 key、有哪些登录方式、
在哪里接受注册（`cn`、`global`），以及它的模型能做什么：`chat`、`vision`（手看屏幕）、`image`（图片）、
`video`（短视频）。

**添加服务商。** 在「设置→模型→添加服务商」中填写自己的API key和端点，或使用当前构建支持的服务商OAuth流程。预设提供名称、端点和`/v1`设置（`minis://settings/providers/add?preset=<id>`）。OpenMinis的`OpenAIOAuthManager`、`ClaudeOAuthManager`、`KimiOAuthManager`和`OpenRouterOAuthManager`仍负责对应认证，具体能否使用取决于服务商和构建配置。Anthropic、Gemini使用各自的服务商类型，其他兼容端点使用OpenAI表单。

Claude 登录需要 Anthropic 要求放在每个请求开头的一段标识；它在构建时从
`app/provider-customization.properties` 读入，这个文件不在仓库里，所以发布的 APK 没有它。没有这段
标识的构建不会列出 Claude 登录（这张卡片上没有，「添加服务商」里没有，`?preset=anthropic:oauth`
打开的是 API key 表单）；早先版本保存下来的 Claude 登录，每次发送都会得到一句「这个版本不能用
Claude 账号登录。请改用 API key 添加 Anthropic。」，而不是让 App 退出（`io.github.nanomuse.cloud.ClaudeSignIn`）。

**列表从哪来。** 服务商预设读取随应用打包的`assets/nanomuse/providers.json`目录，不再向原中继刷新账号推荐数据。

**各家覆盖什么。** 能力决定 App 提供什么（`cloud/Capabilities.kt`）：图片（「设置 → 模型 → 生成图片」、
形象工作室、`nanomuse-media image`）只在厂商有 `image` 的服务商里挑；短视频只在有 `video` 且 App
能驱动的里面挑（百炼的视频 API）；屏幕模型和它的选择页只列出有 `vision` 的厂商的模型。通过
Codex 登录的 ChatGPT 套餐只有聊天和视觉（Codex 后端没有图片或视频端点），所以从不会被拿来
画图。目录不认识的厂商（自己的网关或模型服务器）按它模型自己的说法算，和以前
一样。没有任何已配置的服务商具备某项能力时，页面用一句话说明（「画图需要有图像模型的
提供方：百炼、OpenAI、Gemini 或 OpenRouter。」），而不是报错。

在形象工作室重新生成候选图时，新一组会替换旧一组。旧请求随后返回的图片或失败结果，不会改动新一组的候选格或文件。点击重新生成即可开始新请求，无需等待旧图片保存完毕。

**连不上服务商的时候**（`net/ProviderReach.kt`、`ui/chat/ProviderReachCard.kt`）。失败的一轮，如果
错误来自传输层（OkHttp 的「failed to connect to chatgpt.com/…（port 443）」「Unable to resolve host」、
一条 TLS 或超时信息），或者是 OpenAI 的「region not supported」，就显示为一张卡片而不是红色横幅：
发生了什么、什么有用（这台手机上的 VPN、「设置 → 网络」下的代理、另一家用你自己 key 的服务商）、
「重试」，以及收在「详情」后面的原始信息。上游的 `mapHttpError` 会丢掉 401/403/429 的响应体，
`ReachSignal`（`OpenAIProvider` 里一处 `// nanoMuse:` 改动）把它们留几秒钟，以规范的 `nm_reach:` 行
写进消息，所以过期的 ChatGPT 登录显示「重新登录」，用完的套餐窗口显示「ChatGPT 套餐暂时没有
剩余了」，附 OpenAI 自己的那句话和重置时间；key 服务商上普通的「Invalid API key」则保持上游的
样子。

**服务商拒绝请求时。** 本地错误提示和旧聊天里保存的错误信息仍可显示。内容审核拒绝会明确说明原因，不会通过反复切小同一份内容来重试。原内置中继不能接收新请求，账号登录和Cloud重试入口均已停用。

这些错误出现在聊天里之前，失败的模型请求会先在同一模型上重试，最多6次，依次等待1、2、4、8、15和20秒，期间回复里显示“retrying (n/6)”。断线、超时、5xx、429、什么都没返回就中断的流，以及其他供应商错误都会重试，任务的每一步都是如此，包括工具调用之间的后续步骤。再试也不会改变结果的情况不重试：用户主动停止、密钥被拒（401、403）、内容审核拒绝、模型不存在，以及其他表示请求本身有问题的4xx。重试用完后，模型组才换下一个模型，或者在聊天里显示错误。规则在 `ModelRetryPolicy`，单元测试 `ModelRetryPolicyTest`。

**设置 → 网络**（`net/OwnProviderProxy.kt`、`ui/net/NetworkScreen.kt`、`minis://settings/network`）。
给自己的服务商用的 HTTP 代理：主机、端口、可选的用户名和密码，默认关闭，只存在这台手机上：设置项在
`SharedPreferences` 里，密码单独放在一个 `EncryptedSharedPreferences` 文件里（`nanomuse_proxy_secrets`，
和服务商 key 一样的存法；1.0.3 的手机存在普通文件里的密码会在第一次读取时搬过去）。它在
`MinisApp.onCreate` 中被装为进程默认的 `ProxySelector`，所以每个 OkHttp
客户端每次请求都会问它；对目录里的主机、`chatgpt.com`、`auth.openai.com` 和服务商实例的自定义
base URL（从不包括中继的，从不包括局域网地址）它回答代理，对其他主机，包括沙箱镜像，使用系统设置。服务商客户端带着 `OwnProviderProxy.authenticator`，应付要密码的代理。
「测试」按填写的代理抓取 `https://chatgpt.com/`，报告状态码和毫秒数。单元测试：`ProviderReachTest`、
`OwnProviderProxyTest`。

离开「网络」页，会取消该页尚未完成的请求，服务器已开始回复但还未传完时也一样。

## 语音输入 {#voice-input}

Android 13 及以上的系统连续听写在识别器切换到下一段时会继续传入音频。上一段已关闭管道的写入失败，不会再清除新一段的音频流。

使用服务商语音模型时，静默录音达到时限，或极短语音等待补充超时后，面板会回到空闲状态。已经开始的转写仍会等待结果，不会被空结果提前结束。

系统语音输入可以优先使用设备端识别。手机没有可用的设备端识别服务时，会改用默认识别服务；默认服务返回的语言错误会显示在语音面板中。已经启动的设备端识别器缺少语言包时，仍会尝试一次默认服务。

录音无法启动，或在开始采集前被取消时，语音检测器也会释放已经创建的录音器，避免重试语音输入时留下未释放的录音器。

## 隐私与权限 {#privacy-and-permissions}

聊天、记忆和本地记录保存在应用存储中；模型请求与连接器操作仍会把必要内容发送给你自行配置的服务。服务商密钥与网络代理密码使用加密偏好设置。应用通过`allowBackup="false"`关闭Android系统自动云备份，保留用户主动备份和恢复。重装后不会从原账号服务恢复聊天。

Hands需要可选、可撤销的无障碍和悬浮窗权限。发送内容的操作需要审批，限定当前聊天的授权仍绑定当时的应用或地址。智能体文件路径只能在沙箱内解析（`io.github.nanomuse.sandbox.SandboxPaths`），路径穿越或指向根目录外的符号链接会被拒绝。

App 只对你自己网络内的地址（私有网段 `10/8`、`172.16/12`、
`192.168/16`、Tailscale 分配的 `100.64/10`、链路本地地址、IPv6 ULA、`localhost`、不带点的名字，
以及 `.local`、`.lan`、`.home`、`.internal`、`.home.arpa`、`.localdomain`、`.ts.net` 后缀），也就是一台模型
服务器或你自己的电脑，允许明文 `http://`，其他地址在服务商 URL 字段里一律拒绝
（`io.github.nanomuse.net.LanOnly`）。地址先解析再判断，所以 `10.foo.example.com` 这样的公网名字
不会被当成私有地址。App 内的
web view 不对其他 App 导出。用服务商语音模型做语音输入时，麦克风只在录音期间打开：停止或取消录音都会立刻关掉录音器，取消的那段音频直接丢弃，不会发给服务商。

## 自己构建 {#building-it-yourself}

JDK 17 或 21（CI 用 21）和 Android SDK（Android Studio 会把两个都装上）；`scripts/android/env.sh` 在一台空机器上
设好环境。工程在 `android/src/android` 下：

```bash
bash scripts/android/build-natives.sh   # 只需一次：proot、Alpine rootfs 和 rclone.aar（NDK r27c，Go 1.25+）
cd android/src/android
./gradlew :app:assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease      # signed with android/keystore.properties when present
./gradlew :app:testDebugUnitTest --tests 'io.github.nanomuse.*'   # 我们的单元测试
./gradlew :app:lintDebug            # Android lint；报告在 app/build/reports/lint-results-debug.html
```

Lint 用的是比 AGP 8.7.3 自带版本更新的 lint（`gradle.properties` 里的
`android.experimental.lint.version`）：Compose 和 lifecycle 库自带的检查，自带的那个加载不了。上游树里有
它自己的 lint 发现；看报告时找 `io.github.nanomuse` 的部分。

`rclone.aar` 用 Go 构建，模块走 Go 自己的默认代理（`https://proxy.golang.org,direct`）；在中国大陆网络下先
`export GOPROXY=https://goproxy.cn,direct`，`env.sh` 会沿用你导出的值。

`scripts/rebrand.py` 带着版本号（`VERSION_NAME`、`VERSION_CODE`），把 nanoMuse 的命名套到
OpenMinis 树上；`android/BUILDING.md` 讲原生部分。没有签名密钥时，release 构建用 debug 密钥签名，
能安装，但不能升级一个正式签名的构建。要签名，先创建一次密钥，放在仓库之外：

```bash
keytool -genkeypair -keystore ~/.nanomuse-release/nanomuse.jks -alias nanomuse \
        -keyalg RSA -keysize 4096 -validity 10950
```

然后把它的四个值填进 `android/keystore.properties`（已 git-ignore：`storeFile`、
`storePassword`、`keyAlias`、`keyPassword`）。

仅用于聊天测试的模拟器构建（`-Pnm.abi=x86_64`）会排除缓存中的 arm64 proot 和 Alpine 根文件系统资源。切回默认的 arm64 构建后会重新包含这些资源，无需删除缓存。

## 发布 {#releases}

`.github/workflows/android.yml` 在 `android/` 下每有改动就构建 debug APK（「debug APK · arm64-v8a」
这项检查）。版本由 `scripts/release-apk.sh <version>` 从一个标签做出来：它核对版本号与 `rebrand.py`
和 Gradle 是否一致，用 release 密钥构建 `:app:assembleRelease`，写出
`dist/nanoMuse-<version>-arm64.apk` 和它的 `.sha256`，加 `--publish` 时打上 `v<version>` 标签，
并把两者连同 `docs/releases/v<version>.md` 里的说明一起附到 GitHub release 上。工作区有未提交的改动，
或者提交不在 `main` 上，发布会被拒绝。debug 签名的 APK
永远不进 release，因为正式签名的版本无法覆盖它。`versionName` 必须和标签一致，就像 Python 包的
版本号那样。

| `ui/models/` | 「模型」页、每一行背后的选择页、「用它来做什么」卡片（`minis://settings/models`） |
| `chat/CloudRetry.kt` | 旧错误兼容；应用不再登录内置云服务，因此不会提供Cloud重试 |
| `chat/RoutineWakes.kt`、`ui/chat/NmRoutineWakeRow.kt` | 定时任务的一轮是例程的，不是本人的：`ScheduledAgentRunner` 在提示词发出前先登记一次唤醒，`ChatViewModel` 把它绑到落库的那一行，聊天里这一行只画成一行安静的小字「例程 · 〈名称〉 · 08:00」，而不是一条以本人口吻发出的气泡；模型收到一条只管这一轮的 `SessionAddenda`，说明情况，于是它直接从结果说起，不感谢谁的提问。到 1.0.4 为止，提示词就像本人打的字一样立在聊天里 |
| `feed/` | 动态：`FeedFlow` 维护每日定时任务和它写作所在的会话，这个会话是智能体的工作间，不进抽屉、聊天列表和主聊天的回退（`FeedFlow.hidden`，由 `ChatRepository.observeSessions()`、`MainChat` 和「移到会话」面板读取）；`FeedStore` 存帖子，最新的一天在前，一天之内最新的一批在前、每批保持模型给出的顺序（同一批共享 `created` 时间；`FeedStore.DAY_ORDER`，有单元测试）。智能体在 `/var/minis/feed/YYYY-MM-DD/NN.md` 读帖子，你点过赞的带 `liked: true`：这是一份只读副本（`FeedSandboxScope`，每条 shell 命令前和每次点赞后刷新），不是 App 自己的目录，因为 PRoot 不能把文件夹只读地绑进去，而点赞是本人的，不该由智能体改；没有 `liked` 的帖子只是还没反应，提示词里说明了这不是不喜欢。任务在 App 退到后台时写出了帖子，就发一条点出帖子标题的通知，点开进动态页（`minis://feed`），取代 1.0.4 之前那条带着模型原文、点开进会话的通用「任务完成」通知 |

## 拼图记录标记与只读查询 {#mosaic-records-agent-access}

周、月、季、年的日期数字显示记录状态：已保存生活记录为绿色圆圈，今天及以前没有保存记录为红色圆圈，未来日期没有状态圈。草稿和单纯勾选习惯不算生活记录；只有照片的已保存记录仍算一次记录。加载期间不画红圈，避免误报。今日和选中日期原有的外框保留。

Agent 可以直接在手机沙盒执行：

```sh
minis-jigsaw-cli list --start 2026-10-21 --end 2026-10-27
minis-jigsaw-cli get --date 2026-10-27
minis-jigsaw-cli stats --start 2026-10-01 --end 2026-10-31
minis-jigsaw-cli export --start 2026-10-01 --end 2026-10-31 --format md
```

日期范围包含起止两天，最多 366 天，支持 `--from`、`--to` 别名。省略日期时读取手机所在时区的今天及之前六天。记录所属日期使用用户在 App 选择的日历日期，修改日期后不会按创建时间重新归类；创建、更新时间以手机所在时区的 ISO 时间戳返回，输出的 `timezone` 字段写明时区。

`list`、`get` 和 JSON 导出的 `days` 数组按日期升序排列，包含没有记录的日期。每天都有 `text`、`mood`、`mood_label`、`mood_score`、`habits`、`created_at`、`updated_at` 和 `records`。没有填写的内容为 `null`。`records` 保留同日每条记录的完整文字、创建及更新时间、各自的心情；日级 `text` 用换行连接当天文字；日级心情优先保留当天设置（包括明确清空），没有当天设置时取最后一条记录。`mood` 沿用 App 的原始 1 至 5 数值，分别为很好、好、一般、低落、很差；`mood_score` 为显示给用户的能量，5 分最高。习惯区分完成、跳过和未标记，并按当天生效的历史计划计算。

`list` 和 `export` 默认每页 31 个完整日期，可用 `--limit 1..366` 和 `--offset` 调整。响应的 `has_more`、`next_offset` 指明下一页，最后一页的 `next_offset` 为 `null`。Markdown 也会提示下一页偏移量。季度、年度总结需要读完全部页。`stats` 统计整个请求范围，不使用分页，未来日期单列为 `future_days`，不算漏记。命令不静默缩短正文，超过单次读取数量或输出大小限制时明确报错，请缩小日期范围或页大小。

这些命令只读，不支持修改、删除、`--out` 写文件或隐式导出目录；查询结果只返回 stdout，命令自身不联网、不把正文写入日志。读取数据库时不查询照片内容、路径或 EXIF。可以直接要求 AI「根据我的生活碎片做本周总结，只使用文字和心情」。


## 对话锚点和运行通知 {#conversation-anchors-and-running-tasks}

所有主聊天、旁聊和从归档打开的聊天，右上角菜单均提供「对话锚点」。其中「问题目录」自动列出提问和已标记的重点回复；「书签」集中显示手动标记的消息。输入关键词可在当前对话全文中查找，点击结果回到原文并短暂高亮。回复下方的书签按钮也能添加或取消标记，目录中可标记提问。

书签只在本地保存消息身份，不复制正文，也不改变模型上下文。加载后合并的助手消息仍按数据库来源 ID 定位；跳到较早内容时仅扩大到所需的历史显示窗口。不会调用 AI 建立索引。搜索弹窗独立处理键盘，聊天输入框保持原位。

运行通知取消持续加载的进度条。折叠时显示活动对话数量和一条紧凑摘要，展开后每条运行中对话显示「本轮提问摘要 · 已用时间」。各任务独立计时，开始第二个任务不会重置第一个，完成后停止计时。通知沿用当前宠物形象，同一个通知静默更新，不因每秒计时重复提醒。Android 16 的提升通知也使用标准多行内容样式，不再使用进度样式，实际显示空间由系统和手机厂商决定。

日记右上角的日历弹窗和编辑记录的日期弹窗都显示同一套红绿记录圈。可以切月、输入日期、回到今天；未来日期不画圈，编辑记录时仍不能选择未来日期。弹窗只查询每天已保存记录的数量，不加载图片或日记正文。

## 本地教练训练 {#local-coach-practice}

教练页负责技能档案和存档回顾，右上角入口打开成果、课程记录与课程管理。每项技能在“每日练习”分组里有一条长期训练对话：进入下一单元或换案例都继续用这条对话，单元和案例记在每节课上。每次明确开始的课次单独归档。“今天到这里”结束当前课；问候、更正和普通追问仍属于上一课，不会自动开新课。旧评分与旧练习保留，不换算成新协议的掌握。

教学支持先讲清概念、机制、案例、不同理论、反例与边界，再进行适量练习，用户可随时追问。心理学、精神分析与哲学使用不同的证据标准；对具体人物动机的解释保持为可修正假设，不冒充读心或诊断。这些规则由App提供给用户配置的模型，实际教学质量仍依赖模型，需要真实提供方验证。

理解和应用分别以已保存的用户原话校验。独立作答必须对应事先保存的验证题；提示后回答、模拟表现、现实自报与延迟复核分别记录。最终达成需要理解与应用双维度达标，并经过宿主计时至少24小时后的有效复核。结束一课不等于掌握，也不自动推进单元。

### 按日课节与教案 {#coach-daily-lessons}

每节课记下开始时的本地日期和时区，过了午夜或换了时区，已开始的课节不会被拆开。每节课的开场消息带上日期，所以一条长期对话按天分节。今日训练只有一个主按钮：「开始今日训练」「继续训练」，或者「查看今日结果」加「今天再练一节」。前一天的课节没练完时，页面提供「接着那一节」和「开始今天」；选开始今天会先放下前一天的课节，草稿和还在等反馈的回答一并保留，可以在历次训练里查看。现实行动可以跨天等待。重复点按钮、重试或重开应用，都会接着同一节课。

开新课之前，教练会单独调用一次模型准备教案。备课角色不带任何工具，只能看到这项技能的目标、单元标准、最近的作答、课节摘要和等待中的行动，以及该课程的skill和learning-coach skill。它返回任务、理由、要观察的表现、概念、材料、由浅入深的提示、至少一条随回答变化的教学路径、陌生情境下的独立检验、覆盖的标准、何时复核，以及只给教练看的参考说明。应用逐项校验字段和标准ID，并核对每条引用的回答都是已保存回答的原文；校验不过时让模型修正一次，仍不通过就改用课程里的基础练习，并说明原因。同一天里，晚到的旧教案不会覆盖较新的教案。课节一直使用开课时采用的教案。开始前可以缩短时长，或写下今天的真实需要和材料，改动后会重新备课。

当前表现分别列出当前单元的理解、应用和延迟复核，每项附上最近一条依据的原话、日期、是否用了提示，以及是模拟情境还是自述的真实经历。「下次安排」按固定规则给出：独立完成后换情境，满24小时后做延迟复核；提示后完成就先用小任务验证独立完成；还没有作答就先诊断；有等待回报的现实行动或有异议的评价时优先处理。此前的教案连同状态都保留在列表里。

主要聊天不显示教练档案栏；回顾记录可从教练页或每日练习专题进入。

主要聊天仍可探索目标、建课、审阅提案、明确确认版本、暂停课程与报告现实行动。绑定专题只能访问自己的记录；普通旁聊、定时任务与后台派发不能修改教练档案。成果可跳回聊天原文；编辑或删除来源会撤销依赖证据。删除聊天时可选择保留只读摘录，或同时删除关联专题档案。

普通教学正文与真实用户消息由宿主归档，不要求每轮调用教练工具。整理任务有持久化重试队列，重试只补写档案，不重发模型请求；模型失败或整理失败后仍可正常输入。切换课次前必须处理未完成的整理。输入继续使用普通输入法，教练最终正文使用Android系统TTS，属于完整回复后的分句播放，不是逐字生成时同步朗读。

本地记录在`minis-global/nanomuse/growth/coach-v2/`中使用schema3、原子快照和上一有效备份，兼容读取schema2历史。本次仅实现Android，不更新iOS，也不提供教练档案跨设备同步。

## 本地Android质量改进 {#local-android-quality-updates}

Android应用直接引用构建生成的`app/libs/rclone.aar`本地文件，使用同一份备份库，避免Windows上的Lint将原命名参数依赖声明误解析为路径。依赖检查仍启用，AGP和Lint版本保持现有配置。

API密钥供应商和模型表单在写入失败时保留输入，确认保存成功后才返回。保存按钮内显示进度，写入期间阻止重复点击和返回。模型编辑会拒绝同一供应商下的重复ID；如果原始模型快照已被后台刷新或其他编辑修改，也会拒绝覆盖。此时需要重新打开编辑页，核对最新配置后再修改。修改名称或可见能力开关会保留未编辑的思考上限、文本支持和其他媒体能力。自定义模型改名后只返回一层。

供应商配置以已提交的数据库为准。兼容旧版本的JSON副本尚未写完时，会持久记录待同步状态；副本写入失败或进程中断后，下一次启动不会用旧副本覆盖新数据库。主动删除全部供应商形成的空配置也适用。新增API密钥供应商先确认加密凭证写入，再公开供应商配置；失败重试沿用同一个待保存ID。页面重建后识别已提交的ID并返回，不会覆盖已保存的配置或密钥。离开表单后，模型发现任务由仓库继续执行；供应商已删除，或请求期间配置、凭证发生变化时，迟到结果会被丢弃。

待办编辑页重建后保留原始任务版本和上次提交快照。相同内容重试复用操作ID，修改内容后生成新ID。AI修改待办时，取得数据库事务后和提交前都会重新检查当前聊天授权；授权失效会一起回滚任务、分类、事件和重试记录，等待其他数据库操作的请求也适用。

从专注准备页进入锁机权限、白名单、设置或计划，再返回时保留任务、模式、时长和强制专注选项。暂停后结束会话沿用暂停时刻，次日被锁机计划接管也不会把心得归到新的一天。系统时间回拨不会再构造非法的结束时间区间。碎片导入照片、保存或改日期期间禁用移除照片，只有草稿接受修改后才删除暂存图片。

删除教练证据时会重算受影响的历史单元和当前单元。清除对话档案会同时清理关联专题、课节、行动、派生教案及重复操作记录；其他有效证据仍可支持单元达成。之后开课会重新备课，不再复用来源已清除的教案。

教练页返回时保留滚动位置，打开练习期间显示进度；列表使用稳定key，避免加载和错误提示改变下方正文身份。删除聊天弹窗在后台读取教练关联，等待结果后才允许删除；加载失败或账号变化时保持禁用。每日点子条带在首次素材加载前保留卡片行高度，并随字号调整；切换语言后使用独立加载状态。

抽屉搜索在空间不足时使用紧凑头部，次要操作收进菜单，进入多选时收起键盘。教练课程操作可换行，首页和聊天的名称胶囊随文字增高，通用顶部栏先测量导航与操作按钮，再分配标题宽度；生活碎片编辑器的副标题单行省略。切换标签或打开抽屉后，聊天菜单、弹层、预览及菜单相关的返回处理随聊天可见性关闭。

新聊天先登记账号归属再插入记录，并与账号切换共用迁移边界。迁移在移动目录前使旧教练服务失效，恢复失败时保持空间关闭。偏好、定时任务和目标备份保留供同一进程内重试，身份发布后才刷新动态。删除账号聊天时，只有单条聊天的数据与文件全部清理成功才删除其owner；中途失败会停止迁移，保留其余归属。

账号迁移开始时，旧账号的普通聊天ViewModel会取消正在进行的工作。直接记忆与文件工具、记忆上下文加载、Room消息追加和异步事件日志写入均保留并校验操作发起时的账号代次，迟到操作不能改用新账号继续执行。迁移重试进度保存在内存中，同一进程内可重试不代表杀进程后能够自动恢复。上述保护覆盖这些App入口；外部shell进程及其他后台服务仍需分别核查隔离范围。

定时任务的目标与消息选择器只读取当前账号拥有的聊天，派发时再次核对归属和账号迁移代次。账号变化会取消旧任务，普通教练缓存刷新不会。任务级占用阻止首次重叠运行创建多条专属聊天。复用任务聊天时，将任务当前模型绑定同时应用到已加载聊天和存储，清空绑定则重新解析当前默认；应用失败会恢复原模型，不改变App全局默认。

大段粘贴先显示附件，再在后台写入文件，发送时等待准备完成。准备失败或取消时保留排队内容；普通发送失败恢复时，同时保留原文字、附件和随后输入的新草稿。队列只消费已成功落盘的条目ID。Markdown本地媒体按指定聊天或明确共享目录解析完整路径，不再遍历其他聊天寻找同名文件。音频异步准备，在失败、取消和组件退出时释放资源；Markdown使用按当前配色后台准备的不可变呈现快照，增量流式尾部也一并预热。聊天ViewModel释放时注销安全模式监听。

输入搜索词后直接显示匹配聊天，隐藏分组标题，为横屏键盘上方的结果保留空间。前台服务在发起和提升阶段均处理系统启动限制；被拒绝时停止服务，不自动重启或改换服务类型。这避免限制异常导致应用崩溃，不代表系统禁止时仍能保证后台执行。

### 半透明宠物标题

首页聊天的宠物标题采用单层4dp背景磨砂，底缘逐渐透明。消息可从标题背后滚过，列表顶部仍留出内容边距，让最早的消息能够完整滚出标题区域。磨砂只采样消息列表，不采样宠物动画及标题控件。名称胶囊和圆形按钮使用半透明底色；宠物图片或视频保持清晰，素材自带的背景仍随素材显示。Android12以下降级为半透明色层。

## 专注与分类管理

开始专注后进入沉浸全屏，显示任务、大号计时和暂停/继续操作。结束前需要确认，只保存实际计量的时间。收起界面不停止计时，屏幕常亮可自行开启。解锁或进程重建后恢复同一活动会话，应用不会绕过系统锁屏。

每次开始前可以选择背景。默认山景由矢量绘制。“导入背景”打开系统文件选择器，只将你选中的文件复制到应用私有目录，最多24张，每张20MB。保存后可用于后续专注。删除只移除应用副本，不删除相册原图。背景按账号隔离，不提供给AI工具，失效或缺失时回退山景。

专注工具响应增加`view_url`、`sampledAt`、`currentElapsedMs`和`remainingMs`。重复命令保留首次回执，`isReplaySnapshot`为true时应读取`currentState`确认当前状态。`deadline_reached`表示暂停请求到达时已经到期，不能据此判断为提前暂停。通知与`minis://views/focus`可打开专注页。

待办工具增加`create_category`和`delete_category`，管理可复用分组和标签。删除需要最新分类查询返回的准确名称、类型和`expectedCreatedAt`。删除只解除当前任务分类，同时增加受影响任务的revision，保留任务和历史完成快照。旧请求原样重试不会删除后来重建的目录。分类操作回执使用独立备份字段，兼容旧待办备份。

侧栏待办下方新增“专注”。可选择待办任务，也可直接填写本次专注内容，使用番茄倒计时、正计时或休息计时。暂停时间不累计，倒计时可设1至180分钟，正计时最长12小时。切换页面、锁屏和同一开机周期内重启进程可恢复计时；设备重启后保守暂停。系统省电可能延迟到时通知，但不会多计倒计时时长。专注结束后，全屏计时页提供休息5分钟，当天每完成第4个专注时为15分钟；休息结束后可以按原任务和原时长继续专注。正计时不显示进度条，改为显示开始时刻。

右上入口提供专注记录、日/周/月/年统计和JSON导出。统计按真实计时区间拆分跨日时长，不含休息、未结束或已删除记录。时长占比可以按待办分组看，也可以按标签看；一次专注有多个标签时时长平均分给这些标签，与待办统计一致。离开全屏计时页总是回到专注页。任务详情可回顾投入时长，结束计时不会自动完成待办。

每日记录可选择已结束的专注时段，草稿保存选择，正式提交在同一事务保存日记与关联快照。只有关联、没有正文也能保存。删除专注记录后，已存日记快照仍保留。

普通聊天，包括新建聊天，可通过`focus_query`和`todo_query`读取当前账号的专注与待办。主要聊天还提供`focus_command`及待办修改命令，沿用当前用户、账号隔离、版本校验和风险门禁。模型不能填写过去时间或虚构时长。专注JSON导出包含历史，导入仅恢复停用的锁定计划和白名单，不恢复历史或活动计时。

“待办→分组与标签→浏览与创建”现在可以删除分类。删除分组会保留任务并转为未分组；删除标签会解除当前任务关联。历史完成标签快照不会被改写。

### 专注结束后记录心得 {#focus-reflections}

倒计时自然结束或手动结束专注后，可在沉浸页面、最近记录或历史卡片点击“记录心得”。每日记录编辑器会自动选中本次已完成专注及仍存在的关联待办，初始日期取专注结束的本地日期。关联待办不会将其自动标记完成；修改任务状态仍需在编辑器中明确选择。休息时段不显示心得快捷入口。

沉浸页长标题最多显示两行，结束后收起息屏继续提示，为“记录心得”和返回操作留出空间。

每次专注都有独立的可恢复草稿。再次进入时保留已经修改的文字、日期和关联，包括已经取消勾选的专注或任务，不覆盖同一天的普通碎片草稿。保存时同时提交心得和关联。返回或重建页面不会重复打开编辑器或沉浸计时。

每日记录的文字入口与编辑器统一使用“心得”。记录可保留文字、心情、习惯、所选任务及实际专注时段。任务后来改名、专注记录后来删除时，保存时的标题、状态与计时快照仍可回顾。

### 在普通聊天中复盘记录 {#personal-record-queries}

可以直接在新聊天中要求分析最近的专注、结合待办进度或总结已保存心得。模型在获得本次真实用户回合授权后使用只读工具，无需先把聊天设为主要聊天。修改任务和计时仍需主要聊天及原有明确用户意图校验，教练写入仍限主要聊天或对应专题。

`personal_records_query`提供记录目录、心得历史日期范围、心得正文与统计、教练历史、目标及定时任务运行记录。查询按范围和分页读取；教练、目标、定时任务支持按准确ID查看详情，心得按完整日期分页并保留原文。完整复盘需要读完所有分页；读取失败不能说成没有记录。专注和待办继续使用各自的查询工具。

心得文字和习惯沿用现有设备本地存储；它们关联的待办、专注快照，以及专注、待办、教练、目标和定时任务按当前账号读取。查询不读取照片文件、照片元数据、凭据或未保存的日记草稿。切换账号或取消回合会使请求失效。专注时长不能证明任务完成或注意力质量，心得仍是用户自述；分析质量也取决于所选模型。

Windows构建Debug包时，可用`-Pnm.bash=<Git Bash的绝对路径>`选择暂存调试资源的Bash程序，避免没有Linux发行版时误用Windows的WSL入口。未指定时仍使用`bash`。
