# Android强制专注

强制专注是可选功能，要求Android11及以上。普通专注的开始、暂停、继续、结束、删除和返回键收起行为保持原样。强制专注在固定时段内限制应用访问，无法阻止系统强行停止，也无法保证被厂商冻结后自行恢复。

## 开始专注 {#start}

1. 从专注页右上角进入权限中心，完成五项授权：实际连接的无障碍服务、悬浮窗、使用情况访问、精确闹钟和通知。服务已启用却未连接时，页面提示关闭后重新开启；电池与自启动另行提示。
2. 开始前选择白名单。列表支持搜索系统应用和后台包，没有启动入口的包会标注。电话始终可用；设置、桌面、安装器和语音助手不可选择。
3. 选择倒计时、正计时或定时休息，再开启默认关闭的「本次强制」。强制正计时最长12小时，锁屏页向上计时，并提供「结束专注」：确认一次后保存已计时长并解锁手机。已有普通计时时，先按已计量时长结束，再开始强制专注。
4. 现有全屏专注窗口显示标题、倒计时、背景、拨号按钮和白名单启动器。强制期间没有暂停和结束按钮（强制正计时的「结束专注」除外），返回键也不能收起。

背景沿用现有的本地上传和选择功能，手动强制专注会先绑定所选背景，再打开首屏。亮屏恢复不会让屏幕常亮，也不会主动点亮手机。切换键盘时，输入法窗口立即按系统当前输入法身份判断；键盘设置页仍受普通应用访问规则限制。

## 锁机计划 {#schedules}

从专注选项进入「锁机计划」。一条计划包含名称、启用状态、星期、多个时段、全局白名单开关，以及可选的标题或关联待办。起止相同表示全天，结束早于开始表示跨午夜。跨午夜的时段算在开始那天：周一21:00到06:00在周二06:00结束，之后保持解锁，直到下一次开始。单次上限24小时，夏令时产生的25小时日期也受此限制。

计划支持创建、编辑、启用和删除，并检查修订号。参与当前锁定的计划不能修改。权限不齐不能启用；到点时权限丢失，同一时段提示一次，并在时间窗内每30秒重试，时间窗结束后不补锁。

初始同时生效的计划取最晚结束时刻和最严白名单。后开始的重叠计划立即收紧访问，已经开始的固定倒计时不延长；原计时到期后，仍有效的后续时段以新固定段接续。这是协调重叠计划与固定截止约束的明确调整，连续接续的实际体验仍待真机验证。

具体时段由计划ID、原定本地日期、起止分钟组成，不以转换后的epoch或时区作为身份。完成身份持久保存，改时间或时区不能重放。超过24小时的合并区间截断并消费此次身份，剩余一小时不会自动补锁。

## Nivo、窗口与AI控制 {#chat}

强制期间Nivo自身只显示锁机页。聊天、设置、文件、终端、首页其他标签和深链页面都会被遮住并转回专注；白名单里不能选择Nivo，旧版本保存过的这一项不再生效。

回到桌面、用小窗或分屏打开应用、从通知栏进入设置，都按窗口拦截，而不只看前台应用。这类窗口一出现就盖上触摸遮挡，锁机页回来之前无法长按图标卸载Nivo；随后锁机页无动画地回到前台。电话、当前输入法和白名单应用在遮挡区域之上的部分仍可触摸。Android 12及以上，强制期间会收起通知栏；厂商的控制中心若仍展开，会被上滑收起。遮挡只读取窗口的包名、类型、层级、焦点和位置，以及系统面板的固定控件ID，不读取文字或输入内容。

`FocusStore.command`在读取幂等命令回执之前检查活动锁定。强制期间五种计时动作均返回固定`focus_locked`，检查前先结算过期记录。`FocusAgentBridge`原样保留错误码，并要求模型不得重试或绕过。

强制期间暂停AI无障碍操作、Hands动作和远程截屏。实际动作前再次查询持久锁定，审批等待之后的操作也要复核。

## 紧急退出与设置 {#emergency}

紧急退出默认开启。在锁机页长按申请，等待10分钟后再次明确确认。等待期间继续锁定，电话始终可用；离开或重新打开页面不会重置或跳过等待。申请绑定本次运行ID，最终事务再次核对会话和等待余量。

等待按单调时钟计算并保存剩余量。重启后关机期间不抵扣等待，改墙钟并重启不能跳过。专注本身自然到期仍会正常解除。紧急退出保存实际时长并标记记录，同时消费确认时正在生效的重叠时段，避免刚退出就被同一组计划重新锁住。之后才开始的计划仍有效。

专注设置可在确认说明后关闭紧急退出，活动锁定期间不能修改设置。关闭后，需要等到时、系统强行停止，或重启后撤销权限才能提前解除，单次上限仍为24小时。亮屏恢复另有开关，通话和已放行的前台应用优先。

统计页按日、周、月、年增加强制专注实际时长和紧急退出次数，只统计已结束、未删除且非休息的实际区间，包含紧急退出前的时长；退出次数按退出时刻归入周期。当天与历史卡片显示紧急退出标记。专注结束不会自动完成关联待办，每日碎片继续关联原有专注记录。

## 存储、计时与恢复 {#storage}

`MosaicDatabase`版本7通过显式6→7迁移增加`focus_lock_plans`、`focus_lock_whitelist`、`focus_lock_runs`。原有18张表和`focus_sessions`列保持不变。计划、白名单和运行按`ownerKey`隔离，变更共用现有账号锁和Room事务；代次变化隐藏旧观察数据，空账号键代表离线本地账号。删除账号的本地数据也会清除其锁机设置、紧急等待和诊断，尚未落盘的诊断任务必须重新核对账号代次。

固定截止等于原始开始加时长。同次系统启动中，剩余时间只按单调检查点计算，改系统时间或时区不能提前结束或延长。普通检查点最多每15秒写盘，到期与明确结算除外。每次拦截先判断到期，专注区间与锁定状态在同一事务结算，避免重复记账。已观察到的自然结束按运行身份发送通知，改墙钟或重叠计划接续时也不会被历史时间筛选漏掉。

重启或启动编号未知时，恢复取保存余量与固定截止减当前墙钟中的较小值，再建立新基准。没有跨重启持续运行的可信时钟，无法证明「同时篡改墙钟并重启」与真实经过时长完全相同，关机时长存在平台边界，不能称为完整防篡改。

专注JSON导出增加版本化的`lock`配置，包含计划和白名单。配置恢复合并到当前账号，不导入计时、运行或已计量时长，所有恢复计划先停用以便复核。活动锁定拒绝导入及扩大白名单，通用`.minisbak`格式不变。

## 诊断与开发 {#diagnostics}

空闲时可在专注设置复制或清除本地诊断，最多400条、64KiB。记录只包含固定动作、时刻、包名和窗口类型；守护不读取节点文字、控件描述或输入，也不上传诊断。现有无障碍服务仅加一行元数据转发，并有集成契约测试防止丢失。

调试版保留ADB安全退出通道，正式构建的源码集没有该类或清单声明。两种构建均使用24小时上限。调试出口不能作为紧急退出流程已验收的证据，其测试记录也不能当成真实学习或专注证据。

## 验证与手机验收 {#verification}

P1至P7代码已接入。阶段日志与不可变测试快照只证明编译和逻辑，最终报告记录实际测试数与APK身份。Room设备测试已提供，但尚未连接手机运行；SQLite迁移与schema检查属于补充证据，不能替代Android上的Room执行。

在`android/src/android/`运行仓库检查：

```sh
./gradlew :app:testDebugUnitTest --tests 'io.github.nanomuse.*' --tests 'com.openminis.app.provider.*' --tests 'com.openminis.app.sandbox.*' --console=plain --no-daemon
./gradlew :app:assembleDebug --console=plain --no-daemon
```

P8真机验收仍待完成。请使用至少两家厂商的手机，先测试2分钟短会话，再测试1小时以上会话：

- 普通专注依次开始、暂停、继续、结束、删除，用返回键收起全屏。
- 强制期间尝试主页、返回、最近任务、通知和锁屏快捷方式；应回到专注，白名单应用和输入法仍可用。
- 打开电话，不拨紧急号码；使用普通测试来电，接听、挂断，再确认回到专注。
- 设置、桌面、安装器和助手保持禁止，即使旧配置包含这些包。
- 到时只解除和通知一次，时长准确；再测试划掉任务、清理后台、重启和覆盖安装，观察厂商恢复与无障碍假死。
- 创建3分钟后开始、持续2分钟的计划，息屏等待；再测试重叠、跨午夜和权限缺失。完成时段不应随改时间或时区重放。
- 让AI结束专注或操作系统设置，应明确返回`focus_locked`。
- 在超过10分钟的专注中长按退出，重新打开页面、改时间并重启，不能提前确认；等满后退出，检查标记与实际时长。
- 结束后切换账号，检查计划、白名单、运行和设置互不混用。

拉回速度、桌面与小窗上的触摸遮挡、厂商控制中心、厂商冻结、来电接听、无障碍假死和重启恢复均为待真机验证。更新Nivo之后，请把它的无障碍服务关闭再打开一次，新设置才会生效。本任务没有修改iOS。
