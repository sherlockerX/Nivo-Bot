# Nivo 2.0.13 · Continuity

Android and iOS share version `2.0.13` (build `64`). This release improves chat reliability, restores images within request limits and respects the capacity reported by a custom model endpoint.

## Highlights

- Fixed Android Markdown rendering getting stuck on text such as `#tag` or `#!/bin/sh`, and coordinated foreground service starts and stops.
- Read Android attachments with file and message limits, downsampled images before decoding them into a request, and loaded compacted chats from recent history while retaining older records on disk.
- Added bounded retries for Android streams that end without a completion marker. Paired Responses tool calls with their results and kept call and item identifiers distinct.
- Preserved Android skill metadata during import and edits, and accepted configuration paths containing dotted model names.
- Used endpoint-reported model capacity ahead of catalogue estimates on both platforms, and displayed its source in model settings.
- Fixed iOS iFlytek synthesis transport, duplicated reasoning fields and attachment address escaping. Restored images and browser screenshots use the request size limits.

## Upgrade notes

- **Android:** arm64-v8a, Android 8.0 or later. Keeps `io.github.nivo` and the original release certificate. Install over a matching signed version without uninstalling it first. Older package IDs remain separate installations; see the [migration guide](https://nivo.8666886.xyz/install.html#android-migration).
- **iOS:** arm64, iOS 16 or later. The Release IPA is unsigned and requires self-signing. Existing bundle identifiers and app groups are retained. Signing identity and entitlements affect access to existing data. This fork does not provide TestFlight or App Store distribution.
- Previous release files remain available in the [download catalogue](https://nivo.8666886.xyz/downloads.html).

## Verification

Release verification is in progress. The final release notes will record the actual build, test and artifact verification results before the release is published. Physical-phone installation, upgrade data retention and real model-provider requests require device testing.
