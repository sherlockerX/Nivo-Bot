# Nelan 2.0.9 · Companion

**Nelan `2.0.9` “Companion”** gives the mobile product its Chinese name, 念步, and separates it from the built-in companion, 十七 / Shiqi.

The Android release uses the new product labels and a blue caterpillar explorer as the default pet. Existing custom faces, imported clips and personal assistant names keep their place. Only complete, untouched historical assistant and memory templates qualify for the default-content upgrade.

This is an **Android-only binary release in preparation**. The final Release APK identity, source archive and public download checks are pending. The iOS source contains the corresponding brand and companion changes, but this round has no Xcode build or iPhone validation and produces no new IPA. The retained iOS download remains `2.0.8 (59)` with its original artifact identity and verification record.

## Highlights

- **The product and companion have separate names.** The app displays 念步 in Chinese and Nelan in other languages. The default companion is 十七 / Shiqi. Settings, permission descriptions, notifications, sharing and file entry points use the product name; a saved personal assistant name is preserved.
- **Shiqi is available offline.** The bundled blue caterpillar explorer uses silent videos and matching covers. The wardrobe, description and preview timing follow the new character. Custom pets and imported clips retain their existing priority, and the launcher continues to use the N mark.
- **Default-content upgrades preserve personal edits.** The installer recognizes complete historical SOUL and GLOBAL templates. It replaces an untouched old seed, including an already-seeded GLOBAL file, while leaving custom names, personality text, facts and edited files intact. The new memory refers to SOUL.md for identity and to the available personal-record tools for reading records.
- **Settings describe the available features.** Reachable avatar and settings copy no longer advertises the removed account-sync service. Advanced tools lead with their purpose while retaining actual commands, paths and file formats. About continues to identify nanoMuse and OpenMinis as upstream projects.
- **Brand changes preserve installation contracts.** Application IDs, data directories, URL schemes, signing settings and existing website addresses retain their values. Brand-only generation is separate from version generation. Cloud sync remains disabled.

## Upgrade Notes

- **Android target:** `2.0.9 (60)`, Android 8.0 or later, arm64, application ID `io.github.nanomuse.app`. The build uses the existing release signing configuration. Final certificate comparison and APK verification remain pending until the build finishes; configuration alone does not establish the resulting signature.
- **Existing Android data:** no Room schema, database version or storage-directory change is part of this release. Back up important records and use a package with the same verified signing identity as the installed release. This round has not tested an actual phone upgrade. Do not uninstall an existing copy solely to work around a signing mismatch.
- **iOS remains `2.0.8 (59)`:** the unsigned IPA, corresponding source archive and checksum file are retained. The new source version and brand changes do not change that binary. Personal signing is still required, and this fork does not provide TestFlight or App Store distribution. See the [iOS 2.0.8 notes](v2.0.8.md) for its actual CI and artifact evidence.
- **Platform scope:** there is no new iOS, desktop or server binary in this release. Forced focus and application whitelists remain Android features. iOS provides reminders and user-controlled Guided Access instructions.
- **16KB-page limitation:** the retained rclone `libgojni.so` still has 4KB ELF load-segment alignment. This release does not establish compatibility with 16KB-page Android devices. ZIP alignment alone does not remove this native-library limitation.
- **Source scope:** the [build-input record](v2.0.9-build-inputs.json) records the actual retained local native inputs. Fixed proot-loader binaries retain the documented source reconstruction gap. The release source archive must record its actual source snapshot and dependency coverage; its identity is pending. Neither the input record nor a source archive proves byte-for-byte reproducible APK builds.
