# Nelan 2.0.9 · Companion

**Nelan `2.0.9` “Companion”** gives the mobile product its Chinese name, 念步, and separates it from the built-in companion, 十七 / Shiqi.

The Android release uses the new application ID **`io.github.sherlockerx.nelan`**, new product labels and a blue caterpillar explorer as the default pet. It installs alongside the old `io.github.nanomuse.app` application with separate private data. It cannot update the old installation in place, and a matching signing certificate does not transfer that installation's data or permissions.

This is an **Android-only binary release with local and public HTTP verification complete**. The final new-ID APK, corresponding source archive and checksum file replace the obsolete old-ID candidates. The [public release page](https://nivo.8666886.xyz/releases/android-2.0.9.html) is deployed, and complete downloads of all three files match the verified local sizes and SHA256 hashes. The iOS source contains the corresponding brand and companion changes, but this round has no Xcode build or iPhone validation and produces no new IPA. The retained iOS download remains `2.0.8 (59)` with its original artifact identity and verification record.

## Highlights

- **The product and companion have separate names.** The app displays 念步 in Chinese and Nelan in other languages. The default companion is 十七 / Shiqi. Settings, permission descriptions, notifications, sharing and file entry points use the product name. A custom assistant name can be carried by the supported memory backup; it does not move automatically between packages.
- **Shiqi is available offline.** The bundled blue caterpillar explorer uses silent videos and matching covers. The wardrobe, description and preview timing follow the new character. The launcher continues to use the N mark. Custom pets and imported clips remain in the old app; the current general backup does not migrate their settings or asset directories.
- **Default-content upgrades preserve personal edits.** The installer recognizes complete historical SOUL and GLOBAL templates. It replaces an untouched old seed, including an already-seeded GLOBAL file, while leaving custom names, personality text, facts and edited files intact. The new memory refers to SOUL.md for identity and to the available personal-record tools for reading records.
- **Settings describe the available features.** Reachable avatar and settings copy no longer advertises the removed account-sync service. Advanced tools lead with their purpose while retaining actual commands, paths and file formats. About continues to identify nanoMuse and OpenMinis as upstream projects.
- **The Android installation has a separate identity.** The package changes to `io.github.sherlockerx.nelan`; source namespaces, relative data paths and file-format identifiers remain compatible. The new sandbox does not share the old app's contents. iOS identity and existing website addresses are retained. Cloud sync remains disabled.

## Upgrade Notes

- **Android target:** `2.0.9 (60)`, Android 8.0 or later, arm64, application ID `io.github.sherlockerx.nelan`. The final APK's package, version, ABI and release signature passed inspection, and its certificate matches the previous release. The old `io.github.nanomuse.app` installation remains separate; matching certificates do not make this an in-place update.
- **Existing Android data:** keep the old application installed. Follow the [Android migration guide](https://nivo.8666886.xyz/install.html#android-migration): export supported categories there, save the files outside its private storage, then import them into the new application. This is a partial transfer through existing tools, not a full migration. Private databases, Keystore entries, system permissions and app settings do not transfer merely because relative file names are unchanged. Actual two-app migration has not yet been tested on a phone.
- **iOS remains `2.0.8 (59)`:** the unsigned IPA, corresponding source archive and checksum file are retained. The new source version and brand changes do not change that binary. Personal signing is still required, and this fork does not provide TestFlight or App Store distribution. See the [iOS 2.0.8 notes](v2.0.8.md) for its actual CI and artifact evidence.
- **Platform scope:** there is no new iOS, desktop or server binary in this release. Forced focus and application whitelists remain Android features. iOS provides reminders and user-controlled Guided Access instructions.
- **16KB-page limitation:** the retained rclone `libgojni.so` still has 4KB ELF load-segment alignment. This release does not establish compatibility with 16KB-page Android devices. ZIP alignment alone does not remove this native-library limitation.
- **Source scope:** the archive is fixed to APK source commit `905f9f23cba0017083a3fc50f3d443a7ade55f9b` and contains 4,892 source files. Its critical files match the working source. The proot submodule is expanded; iSH and its nested iOS submodules are not. The [build-input record](v2.0.9-build-inputs.json) records the retained local native inputs, including fixed proot-loader binaries with a source reconstruction gap. External dependencies and toolchains are still required; byte-for-byte APK reproduction is not verified. Final verification documentation belongs to a subsequent publication commit, without changing this fixed source archive or the APK's recorded source commit.

### Moving from the old Android package

The existing `.minisbak` format records platform/version information, not an application-ID restriction. Its optional encryption derives keys from the backup passphrase, so importing an exported package does not require the old app's Android Keystore. The new app stores imported secrets under its own local credential store. This is a source review of the supported routes, not proof that all user data has been migrated.

| Content | Existing transfer route and limits |
|---|---|
| Chats and their files, shared files, skills | Select the corresponding `.minisbak` categories. Chat attachments require chat-file inclusion; file-size caps can omit content. Inspect missing, skipped and failed-category counts after import. |
| SOUL, GLOBAL, USER and daily memory files | Select Memory in `.minisbak`. Import copies those files over same-named files in the destination. Use the fresh new app before making new memory edits, and restart after import to reload them. Only complete historical default templates qualify for later default-content upgrades. |
| MCP server configuration | Select MCP Servers in `.minisbak`. The configuration file is copied verbatim and replaces the destination configuration. The credentials toggle does not strip secrets embedded in this file. Review local paths and credentials and check each server after import. |
| Providers, models, custom thinking rules and secrets | Select Providers and include credentials when exporting. API keys, supported OAuth token records and manual bearer tokens travel in `secrets.json`. Existing target credentials are kept. A passphrase protects the exported package; an unencrypted credential backup exposes its readable contents. Provider token expiry and live authentication still require checking. Default model selections are device settings and may need to be chosen again. |
| Environment variables | Select Environment Variables and include credentials to carry values. Without credentials, newly restored entries have empty values. Existing variable names are kept rather than overwritten. |
| Todo | Use the separate Todo JSON export/import. Tasks, categories and history are imported under the destination's current local owner. Existing task IDs are kept. Links to missing life-log entries are skipped and counted; a Todo import does not restore those entries. |
| Focus | The separate Focus JSON exports sessions and spans, but the implemented importer restores only lock plans and the application whitelist. Restored plans are disabled. It does not restore focus history, active timers or lock sessions. Check task references after importing Todo, then explicitly re-enable suitable plans. |
| Life-log records and photos, Coach progress, custom pets, scheduled routines and general app settings | The general `.minisbak` exporter does not include their database, private directories or preferences. No complete migration route for them was established in this review. Keep the old application as their existing copy. |

System grants belong to the new package and UID. Check or grant notifications, camera/microphone/media access, accessibility, overlay, usage access, exact alarms, battery exemption and document-tree access again as needed. Device Owner and lock-task authority are not part of a backup and cannot be assumed to move to the new package. Do not remove an existing device administrator or owner merely to complete an unverified migration.

Phone acceptance should first install both packages together and verify that the old app still opens its records. Export an encrypted general backup with the desired categories and credentials, plus separate Todo and Focus JSON files. Import into the new app, inspect every category report, restart, then compare sample conversations, attachments, memory, provider/model selections and tasks. Check that focus plans remain disabled until reviewed. Reauthorize required permissions and test a short ordinary focus session before any strict lock. Confirm the old app still holds the data not covered by the backup. Keep both installations and exported files until these checks are complete.

### 旧Android应用的数据迁移范围

`.minisbak`格式不检查旧applicationId，口令加密由备份口令派生密钥，不依赖旧应用的AndroidKeystore。导入的凭据会写入新应用自己的凭据存储。以下为代码支持范围，不能替代真实迁移验收。

- **通用备份**可携带聊天及勾选的附件、共享文件、技能、SOUL／GLOBAL／USER与日记、MCP配置、服务商和模型、自定义推理规则、环境变量。附件可能受“包含聊天文件”和文件大小上限影响，恢复后须检查缺失、跳过及失败计数。记忆和MCP配置会覆盖新应用中同名目标文件，建议在新应用尚未写入个人内容时恢复，恢复后重启。MCP配置原样复制，“包含凭据”开关不会清除其中的内嵌密钥；本地路径与凭据须另行核对，并逐个验证服务器。
- **密钥与登录资料**须在导出时包含凭据。APIkey、支持的OAuth记录和手动bearer token可随`secrets.json`迁移；新应用已存在的凭据会保留。请用备份口令加密，未加密的凭据备份内容可被直接读取。Token是否过期、供应商是否仍接受登录须另行检查，默认模型选择可能需要重设。环境变量未包含凭据时只恢复名称与空值，已有同名变量不覆盖。
- **待办**使用单独JSON导出与导入，任务、分类和历史归入新应用当前本地owner，已有同ID任务保留。缺失心得记录的关联会跳过并计数，待办文件不会创建这些心得。
- **专注**可以导出计时记录和区间，但现有导入只恢复锁定计划与应用白名单，计划强制停用。它不恢复专注历史、活动计时或锁定会话。先导入待办，再检查计划中的任务关联并手动启用合适的计划。
- **心得及照片、教练进度、自定义宠物、周期任务和通用偏好**不在通用备份的数据库、目录或设置覆盖范围内；本次没有确认它们的完整迁移入口，应保留旧应用作为原始副本。

系统授权按新包及UID重新确认，包括通知、相机／麦克风／媒体、无障碍、悬浮窗、使用情况访问、精确闹钟、电池限制豁免和文件目录授权。Device Owner及lock-task授权不会通过备份转移，不应为了尚未验证的迁移直接移除原设备管理员或所有者。

手机验收先安装并存的新包，确认旧应用记录仍可打开，再从旧应用导出带口令与所需凭据的通用备份，以及待办和专注JSON。在新应用导入后逐项查看恢复报告，重启并对照聊天、附件、记忆、模型选择和待办；检查专注计划保持停用直到确认。重新授予所需权限，先测试短时普通专注，再验证强制锁定。确认未覆盖的数据仍可在旧应用访问，在这些步骤完成前保留两个应用和导出文件。
