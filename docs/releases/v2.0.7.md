# Nivo Bot 2.0.7 · Anchor

**Nivo Bot `2.0.7` “Anchor”** makes Android provider settings, task edits and saved practice records more reliable.

Provider and model forms wait for storage to finish and keep failed inputs available for retry. Task edits retain the revision they started from. Focus reflections preserve the actual pause date, and removing Coach evidence recalculates the affected progress.

## Highlights

- **Provider settings survive failed writes.** The database and its JSON mirror keep a recoverable synchronization marker. A stale mirror no longer silently replaces newer settings. API-key forms wait for confirmed credential and configuration storage before closing.
- **Model edits preserve capabilities.** Renaming a model keeps its unedited media and reasoning settings, rejects duplicate IDs and refuses to overwrite a model changed elsewhere. Late model-list responses cannot restore a deleted provider or write results from an old endpoint.
- **Tasks keep their edit context.** A restored editor retains its original revision and retry snapshot. AI task mutations check the current user's authorization inside the database transaction.
- **Focus and reflections retain their meaning.** Returning from lock settings preserves the prepared session. Ending a paused session handles clock rollback and dates the reflection to the pause, rather than a later settlement. Removing a photo is disabled while its fragment is being saved.
- **Coach keeps progress tied to evidence.** Deleting an answer recalculates the historical units it supported. Purging a conversation removes its derived lesson plans. The skill list and lesson-preparation settings are included in this Android package.
- **Releases can ship one platform at a time.** The publishing tool validates the platforms actually present in the release catalogue. Existing iOS downloads remain available without claiming a new iOS build.

## Upgrade Notes

- **Android package:** version `2.0.7 (58)`, Android 8.0 or later, arm64-v8a, application ID `io.github.nanomuse.app`.
- **Signing identity:** this release uses the existing dedicated Nivo certificate, SHA-256 `9513428b8daaf23fe211b8b63d7830737d0468aaea360b49acaf88bb6de1d6a3`. An update can retain the installed application's data only when its package identity and signing lineage are compatible. The isolated `.uitest` Debug application is a separate installation with separate data.
- **Data compatibility:** this change does not alter the Room schema, database versions, account identity or storage directories. No phone was connected for an actual old-installation upgrade test. Back up important records and install the update over the existing compatible release; do not uninstall merely to replace a package with an incompatible signature.
- **Platform scope:** only Android has a new binary in this release. Shared source version fields move together, but this does not establish a new iOS, desktop or server package. The website retains the iOS IPA that was actually published, with personal signing still required.
- **16KB memory-page limitation:** the retained rclone native library has 4KB ELF alignment. This release does not establish support for 16KB-page Android devices; related remote-backup functionality may be affected. Updating ZIP alignment alone does not resolve this library limitation.
- **Source scope:** the downloadable source is exported from the recorded Android build commit and includes the pinned proot source. The archive manifest identifies unexpanded iOS dependencies and the existing fixed proot-loader binaries that cannot be reproduced from this tree alone. The archive is not a claim of byte-for-byte reproducible APK builds.

### Verification

The local arm64 Release build succeeded with R8 code shrinking enabled. The final APK is **40,969,779 bytes** (40.97MB), SHA-256 `c71df8cf358ecbebfc8fa8ea7fda8062cce84a9be3b5b5edd86c4622cf9a8494`. APK signature verification, package/version/ABI checks and ZIP integrity passed. The certificate matches the prior dedicated release; the APK is not debuggable and contains no forced-focus Debug receiver or start/stop actions. Retained native inputs and their checksums are listed in the [build-input record](v2.0.7-build-inputs.json).

The Android audit ran 1,933 JVM tests: 1,931 passed, none failed and two were skipped. Debug application and instrumentation APK packaging succeeded; the instrumentation tests were not executed on a device. The single-platform publishing tests passed all 39 cases.

The source ZIP is exported from commit `449324dae61f183c4a08f748252662e759ecb34e`, whose Android application sources match the verified build. It contains 4,819 committed source entries plus `SOURCE_RELEASE.json`, including the pinned proot submodule. Its size is 62,428,057 bytes and SHA-256 is `409c41d047fcc4833eb1a97b9ce2aa2fea3426a2de757540825ce8491b7c548d`. Later release metadata changes update website records and these notes without changing the APK source.

Android Lint completed but did not pass: 660 errors and 1,050 warnings remain. The audit traced the reported errors to existing translation keys and code outside the changed lines; this is not a clean Lint result. No baseline or suppressed rules were added to make the release pass.

Real-device upgrade retention, rendering and frame timing, actual provider requests, incoming calls, forced-focus enforcement and manufacturer background behavior remain unverified. Build and unit-test results do not replace these checks.
